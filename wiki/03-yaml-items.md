# Предметы в YAML

## Что ты узнаешь

- что такое YAML-предмет и где лежит его файл на сервере;
- как устроен файл: верхний ключ — это ID предмета, в одном файле может быть несколько предметов;
- полный список ключей: тип, значение по умолчанию, что делает ключ и маленький пример;
- как выглядит готовый предмет целиком — большой пример с комментариями на каждой строке;
- как в описании (`lore`) работают подстановки `%cooldown%` и `%uses%`;
- какие ошибки чаще всего допускают новички и почему из-за них предмет «не работает».

## Предусловия

- Плагин DC-CustomItems установлен, сервер запускается — см. [Установка](01-getting-started.md).
- Вы понимаете, как устроена папка плагина и что такое файл конфигурации, — см. [Как это работает](02-how-it-works.md).
- Для применения изменений понадобится команда `/ci reload` — см. [Команды](08-commands.md).
- Если логику предмета невозможно выразить в YAML, посмотрите [Предметы в Java](04-java-items.md).
- Общий список страниц — в [Содержании вики](README.md).

## Что такое YAML-предмет

**YAML-предмет** — это обычный предмет Minecraft, которому плагин добавляет поведение: эффекты зелий, атрибуты, зачарования, реакцию на клики, рецепты крафта и так далее.

Описание предмета пишется в файле `.yml` (YAML — формат конфигурации, в котором ключ идёт перед двоеточием, а значение — после). Никакого программирования для этого не нужно.

Плагин читает все ключи из файла и на их основе собирает «настоящий» предмет в инвентаре игрока: с нужным материалом, названием, описанием, зачарованиями и скрытой меткой, по которой плагин узнаёт предмет позже.

## Где лежит файл

Файлы предметов лежат в папке `items/` рядом с `config.yml`:

```text
plugins/DC-CustomItems/
├── config.yml            ← настройки плагина (не предметы)
├── items/
│   ├── runes.yml         ← предметы из этого файла
│   ├── armor.yml
│   └── messages.java
└── data.db
```

Правила:

| Правило | Подробности |
|---------|--------------|
| Расширение | `.yml` или `.yaml` (оба варианта работают) |
| Имя файла | Любое. Имя файла **не** является ID предмета |
| Содержимое файла | Может содержать **несколько** предметов — каждый верхний ключ = отдельный предмет |
| Папка | `items/` создаётся автоматически, если её нет |
| Файлы `EXAMPLE-*` | Игнорируются — это примеры, они никогда не загружаются |

Чтобы удалить предмет — удалите его ID из файла (или удалите сам файл) и выполните `/ci reload`.

> Старые установки: предметы можно было держать прямо в `config.yml`. Такой способ работает и сейчас, но при загрузке из `config.yml` плагин пропускает служебные ключи (`debug-mode`, `database`, `set-bonuses`, `backup` и другие). Новые предметы кладите в `items/` — так чище.

## Как предмет узнаётся сервером

Каждому предмету плагин ставит в служебные данные (`PersistentDataContainer`, сокращённо PDC) метку с ID предмета. Это невидимая служебная информация, которая хранится вместе с предметом в инвентаре.

Благодаря этому:

- предмет переживает перезагрузку сервера и остаётся «своим»;
- потерянный и найденный предмет снова работает;
- можно точно понять, какой это предмет, а не сравнивать по названию.

Итог: **ID предмета — это верхний ключ в YAML**. Он используется в командах (`/ci give <id>`), в рецептах (как ингредиент) и в правах.

## Полный пример предмета

Ниже — предмет, в котором заполнены **все** ключи. Ключи, которые обычно не нужны, всё равно показаны, чтобы вы видели их имена и формат.

```yaml
# ID предмета. Это имя используется в командах и рецептах.
ember-blade:

  # ---- Основные параметры ----

  # Тип предмета: RUNE, TOOL, ARMOR или CONSUMABLE.
  type: TOOL

  # Слот, в котором предмет работает: HAND, OFFHAND, HEAD, CHEST, LEGS, FEET.
  activation-slot: HAND

  # Можно ли поставить предмет как блок.
  placeable: false

  # Право, без которого предмет нельзя использовать. Пусто — ограничений нет.
  permission: customitems.ember-blade

  # Кулдаун между кликами в миллисекундах. 3000 = 3 секунды.
  click-cooldown: 2000

  # Сколько раз предмет можно использовать. -1 (или отсутствие ключа) = бесконечно.
  max-uses: 25

  # Время жизни предмета в секундах. -1 = навсегда.
  duration: 300

  # Сообщение, когда время жизни закончилось.
  max-duration-message: '&cМеч рассыпался в пепел!'

  # ---- Эффекты зелий (пока предмет в слоте активации) ----
  # Формат: ЭФФЕКТ:УРОВЕНЬ. Уровень 1 — обычный, 2 — усиленный.
  effects:
    - 'INCREASE_DAMAGE:2'
    - 'FIRE_RESISTANCE:1'

  # ---- Описание предмета ----
  # %cooldown% и %uses% подставляются автоматически (см. раздел «Подстановки в lore»).
  lore:
    - ''
    - ' &7Клинок из живого пламени.'
    - ''
    - ' &eПКМ: &fВзрыв огня'
    - ' &eЛКМ: &fПоджог'
    - ''
    - ' &7Заряды: &b%uses%'
    - ' &7Перезарядка: &b%cooldown% &7сек.'
    - ''

  # ---- Действия при кликах ----
  # Полный список действий — в разделе [Действия](05-actions.md).
  left-click-actions:
    - 'effect:FIRE_RESISTANCE:5:1'
    - 'particles:FLAME:30'
  right-click-actions:
    - 'damage_nearby:12:4'
    - 'particles:EXPLOSION_NORMAL:25'
    - 'sound:ENTITY_GENERIC_EXPLODE:1:1'

  # ---- Триггеры (реакция на игровые события) ----
  # Полный список триггеров — в разделе [Триггеры](06-triggers.md).
  triggers:
    on_equip:
      - 'particles:FLAME:40'
      - 'message:&6Пламя вспыхнуло!'
    on_kill:
      - 'heal:10'
      - 'effect:REGENERATION:8:2'

  # ---- Рецепты крафта ----
  # Подробнее — в разделе [Рецепты](07-recipes.md).
  recipes:
    shaped:
      - pattern:
          - ' A '
          - 'ABA'
          - ' A '
        keys:
          A: DIAMOND
          B: STICK
        amount: 1

  # ---- Ограничения по мирам ----
  allowed-worlds:
    - world
    - world_nether
  disabled-worlds:
    - world_the_end

  # ---- След из частиц за игроком ----
  trail-particles:
    - 'FLAME:6'
  trail-particle-interval: 3

  # ---- Частицы и звуки при надевании / снятии ----
  equip-particles:
    - 'FLAME:20'
  equip-sounds:
    - 'ITEM_TRIDENT_RETURN:1:1.2'
  unequip-particles:
    - 'SMOKE:10'
  unequip-sounds:
    - 'ITEM_TRIDENT_HIT:0.8:0.8'

  # ---- Сообщения ----
  equip-message: '&6Меч в руке!'
  unequip-message: '&cМеч убран.'
  cooldown-message: '&cПодождите ещё {seconds} сек.'
  activation-message: '&aСпособность активирована!'
  deactivation-message: '&cСпособность выключена.'
  uses-depleted-message: '&cМеч сломался!'

  # ---- Внешний вид (секция item) ----
  item:
    type: NETHERITE_SWORD          # материал (обязательный ключ)
    title: '&6[🔥] &fМеч Углей'     # отображаемое имя
    amount: 1                      # размер стака
    glowing: true                  # предмет переливается (свечение зачарований)
    unbreakable: true              # нельзя сломать
    texture: 'eyJ0ZXh0dXJlcyI6...' # текстура — только для PLAYER_HEAD
    custom-model-data: 1001        # старая модель (для ресурс-паков)
    item-model: 'minecraft:item/netherite_sword'   # новая модель (1.21.2+)
    item-model-variant: 'ember_blade_animated'     # вариант модели (анимация)
    enchantments:
      SHARPNESS: 4
      FIRE_ASPECT: 2
    item-flags:
      - HIDE_ATTRIBUTES
      - HIDE_UNBREAKABLE
    attributes:
      GENERIC_ATTACK_DAMAGE: 8.0
      GENERIC_MAX_HEALTH: 4.0
    armor-set: ember-knights       # ID набора брони
    has-set-bonus: true            # брать бонус за полный набор
```

## Ключи уровня предмета

Эти ключи пишутся **рядом** с секцией `item:`, на одном уровне с ней.

### type

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | `RUNE` |
| Допустимые значения | `RUNE`, `TOOL`, `ARMOR`, `CONSUMABLE` |

Тип предмета. Он влияет на поведение:

- `CONSUMABLE` — при использовании эффекты применяются один раз, а сам предмет расходуется (одна штука из стака);
- остальные типы эффекты держат, пока предмет лежит в слоте активации;
- `ARMOR` и `RUNE` — обычные постоянные предметы, разница только в вашем описании и в слоте активации.

Регистр не важен: `tool` и `TOOL` — одно и то же. Если написать неизвестное значение, плагин напишет предупреждение в консоль и возьмёт `RUNE`.

```yaml
type: TOOL
```

### activation-slot

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | `HAND` |
| Допустимые значения | `HAND`, `OFFHAND`, `HEAD`, `CHEST`, `LEGS`, `FEET` |

Слот, в котором предмет «работает». Пока предмет не в этом слоте, его эффекты и атрибуты не действуют.

| Слот | Что это |
|------|---------|
| `HAND` | Основная рука |
| `OFFHAND` | Вторая рука (левая) |
| `HEAD` | Шлем |
| `CHEST` | Нагрудник |
| `LEGS` | Поножи |
| `FEET` | Ботинки |

Неизвестное значение → предупреждение в консоль и `HAND`.

```yaml
activation-slot: OFFHAND
```

### placeable

| Что | Значение |
|-----|----------|
| Тип | булево (`true` / `false`) |
| По умолчанию | `false` |

Разрешено ли ставить предмет как блок в мир. Если `false` — установка блока отменяется (без сообщения).

```yaml
placeable: false
```

### permission

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | нет ограничения |

Право (permission), которое нужно игроку, чтобы пользоваться предметом. Если у игрока нет этого права, клик отменяется и выводится сообщение «У вас нет прав на этот предмет».

Права настраиваются в плагине вроде LuckPerms или в `permissions.yml` — см. [Права](15-permissions.md).

```yaml
permission: customitems.ember-blade
```

### click-cooldown

| Что | Значение |
|-----|----------|
| Тип | число (целое) |
| По умолчанию | `0` (кулдауна нет) |
| Единица | миллисекунды |

Пауза между кликами по предмету. Пока она не истекла, клик полностью игнорируется: ни действия, ни триггеры не выполняются.

В lore при этом подставляется оставшееся время в секундах через `%cooldown%`.

```yaml
click-cooldown: 3000   # 3 секунды
```

### max-uses

| Что | Значение |
|-----|----------|
| Тип | число (целое) |
| По умолчанию | `-1` (без ограничения) |
| Значения | `0` и `-1` = бесконечно, положительное число = количество применений |

Счётчик зарядов. Счётчик хранится прямо в предмете, поэтому у каждой копии свой запас. Когда заряды кончились, предмет удаляется из руки, а игрок видит `uses-depleted-message`.

```yaml
max-uses: 25
```

### duration

| Что | Значение |
|-----|----------|
| Тип | число (целое) |
| По умолчанию | `-1` (вечный предмет) |
| Единица | секунды |

Время жизни предмета. Отсчёт начинается с момента, когда предмет попал к игроку (в инвентарь). Когда время истекло — предмет исчезает, игрок видит `max-duration-message` (или стандартное сообщение об истечении срока).

Проверка идёт раз в секунду, поэтому предмет может пролежать в инвентаре до секунды дольше.

```yaml
duration: 300   # 5 минут
```

### max-duration-message

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | стандартное сообщение плагина («Предмет истёк») |

Сообщение, которое видит игрок, когда срок жизни предмета закончился. Пустая строка `''` — сообщение не показывается.

```yaml
max-duration-message: '&cМеч рассыпался в пепел!'
```

### effects

| Что | Значение |
|-----|----------|
| Тип | список строк |
| По умолчанию | пустой список |

Зелья, которые действуют, пока предмет находится в слоте активации (и при клике для `CONSUMABLE`).

Формат строки: `ИМЯ_ЭФФЕКТА:УРОВЕНЬ`. Уровень `1` — обычное зелье, `2` — усиленное (как Strength II) и так далее. Если двоеточия нет, строка молча игнорируется.

Эффекты нескольких предметов складываются по максимуму, а не суммируются: Strength I + Strength II = Strength II.

```yaml
effects:
  - 'INCREASE_DAMAGE:2'   # Сила II
  - 'SPEED:1'             # Скорость I
  - 'FIRE_RESISTANCE:1'   # Огненное сопротивление
```

Полный список имён эффектов — в разделе [Действия](05-actions.md).

### lore

| Что | Значение |
|-----|----------|
| Тип | список строк |
| По умолчанию | пустой список |

Описание предмета — серый текст под названием. Именно здесь работают подстановки `%cooldown%` и `%uses%` (см. [Подстановки в lore](#подстановки-в-lore)).

Важно: если в файле есть верхний ключ `lore`, он **заменяет** описание из секции `item:`. Оба ключа одновременно использовать не нужно.

```yaml
lore:
  - ''
  - ' &7Меч из живого пламени.'
  - ''
  - ' &7Заряды: &b%uses%'
  - ''
```

### left-click-actions

| Что | Значение |
|-----|----------|
| Тип | список строк |
| По умолчанию | пустой список |

Что происходит при клике **левой** кнопкой мыши по предмету. Каждая строка — одно действие, например `effect:SPEED:10:1` или `message:&aГотово!`.

Если список не пустой, клик отменяется (блок не ломается, лук не стреляет) — так же работают предметы в ванильном Minecraft.

Полный список действий — в разделе [Действия](05-actions.md).

```yaml
left-click-actions:
  - 'particles:FLAME:30'
  - 'sound:ENTITY_BLAZE_SHOOT:1:1'
```

### right-click-actions

| Что | Значение |
|-----|----------|
| Тип | список строк |
| По умолчанию | пустой список |

То же самое, но для **правой** кнопки мыши (ПКМ).

```yaml
right-click-actions:
  - 'damage_nearby:12:4'
  - 'particles:EXPLOSION_NORMAL:25'
```

### triggers

| Что | Значение |
|-----|----------|
| Тип | карта (имя триггера → список действий) |
| По умолчанию | пусто |

Реакция предмета на игровые события: надевание, снятие, прыжок, убийство, получение урона и так далее. В отличие от `left-click-actions`, здесь у каждого действия есть свой «повод».

```yaml
triggers:
  on_equip:
    - 'message:&6Меч в руке!'
  on_jump:
    - 'effect:SPEED:3:1'
  on_kill:
    - 'heal:10'
```

Полный список триггеров — в разделе [Триггеры](06-triggers.md).

> Старый ключ `trigger-actions` удалён начиная с версии 1.328 и игнорируется. Перенесите действия в секцию `triggers:`.

### recipes

| Что | Значение |
|-----|----------|
| Тип | карта (тип рецепта → список рецептов) |
| По умолчанию | пусто |

Рецепты крафта этого предмета. Поддерживаются `shaped` (по форме), `shapeless` (без формы), `furnace` (в печи), `smithing` (в кузне) и `stonecutting` (в камнерезе).

Ингредиентом может быть материал (`DIAMOND`) или ID другого кастомного предмета — YAML или Java.

```yaml
recipes:
  shaped:
    - pattern:
        - ' A '
        - 'ABA'
        - ' A '
      keys:
        A: DIAMOND
        B: STICK
      amount: 1
  shapeless:
    - ingredients:
        - DIAMOND
        - DIAMOND
      amount: 1
  furnace:
    - ingredient: IRON_INGOT
      experience: 0.7
      cooking-time: 200
```

Подробнее — в разделе [Рецепты](07-recipes.md).

### allowed-worlds и disabled-worlds

| Что | Значение |
|-----|----------|
| Тип | список строк (имена миров) |
| По умолчанию | пусто (предмет разрешён везде) |

`allowed-worlds` — белый список: предмет работает только в перечисленных мирах.
`disabled-worlds` — чёрный список: предмет не работает в перечисленных мирах.

Если игрок с запрещённым предметом заходит в запрещённый мир, предмет удаляется у него из инвентаря, а игрок получает сообщение «Предмет запрещён в этом мире».

```yaml
allowed-worlds:
  - world
  - world_nether
disabled-worlds:
  - world_the_end
```

### trail-particles и trail-particle-interval

| Что | Значение |
|-----|----------|
| Тип | список строк / число (целое) |
| По умолчанию | пустой список / `5` |

След из частиц за игроком, пока предмет в руке.

Формат частицы: `ИМЯ_ЧАСТИЦЫ:КОЛИЧЕСТВО` (количество по умолчанию — 5).

`trail-particle-interval` — через сколько тиков появляется следующая порция. 20 тиков = 1 секунда. Значение `0` или меньше отключает след.

```yaml
trail-particles:
  - 'FLAME:6'
  - 'LAVA:2'
trail-particle-interval: 3
```

### equip-particles, equip-sounds, unequip-particles, unequip-sounds

| Что | Значение |
|-----|----------|
| Тип | список строк |
| По умолчанию | пусто |

Частицы и звуки в момент надевания и снятия предмета.

Формат частицы: `ИМЯ_ЧАСТИЦЫ:КОЛИЧЕСТВО` (по умолчанию 10).
Формат звука: `ИМЯ_ЗВУКА:ГРОМКОСТЬ:ТОН` (по умолчанию `1:1`).

```yaml
equip-particles:
  - 'FLAME:20'
equip-sounds:
  - 'ITEM_TRIDENT_RETURN:1:1.2'
unequip-particles:
  - 'SMOKE:10'
unequip-sounds:
  - 'ITEM_TRIDENT_HIT:0.8:0.8'
```

### Сообщения предмета

Все эти ключи необязательные. Если ключ отсутствует или его значение пустое, игрок не получает никакого сообщения (кроме случая с `uses-depleted-message` — там есть запасной вариант в самом плагине).

| Ключ | Когда показывается | Значение по умолчанию |
|------|--------------------|-----------------------|
| `equip-message` | Предмет наделен | нет |
| `unequip-message` | Предмет снят | нет |
| `cooldown-message` | Клик во время кулдауна | нет |
| `activation-message` | Предмет вступил в силу | нет |
| `deactivation-message` | Предмет перестал действовать | нет |
| `uses-depleted-message` | Заряды кончились | сообщение плагина |

В `cooldown-message` есть подстановка `{seconds}` — сколько секунд осталось ждать (например `2.5`).

```yaml
equip-message: '&6Меч в руке!'
unequip-message: '&cМеч убран.'
cooldown-message: '&cПодождите ещё {seconds} сек.'
activation-message: '&aСпособность активирована!'
deactivation-message: '&cСпособность выключена.'
uses-depleted-message: '&cМеч сломался!'
```

## Секция item

Секция `item:` описывает, как предмет выглядит. Без неё предмет не загрузится — плагин напишет в консоль «Section 'item' not found for item: <id>» и пропустит его.

### item.type

| Что | Значение |
|-----|----------|
| Тип | строка — название материала Minecraft |
| По умолчанию | `STONE` |
| Пример | `DIAMOND_SWORD`, `PLAYER_HEAD`, `NETHERITE_HELMET` |

Материал, на основе которого делается предмет. Название можно писать в любом регистре, через дефис или с префиксом `minecraft:` — `diamond_sword`, `DIAMOND_SWORD` и `minecraft:diamond_sword` эквивалентны.

Материал `AIR` (воздух) использовать нельзя — предмет не загрузится. Неизвестный материал — в консоль уйдёт предупреждение.

```yaml
item:
  type: NETHERITE_SWORD
```

### item.title

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | нет названия (будет стандартное имя материала) |

Отображаемое имя предмета. Поддерживаются цвета `&` и `§`, а также форматирование `&l` (жирный), `&n` (подчёркнутый), `&o` (курсив), `&m` (зачёркнутый), `&k` (случайные буквы), `&r` (сброс).

```yaml
item:
  title: '&6[🔥] &fМеч Углей'
```

### item.lore

| Что | Значение |
|-----|----------|
| Тип | список строк |
| По умолчанию | пустой список |

Описание предмета без подстановок. Если в файле есть верхний ключ `lore`, он заменит это описание.

```yaml
item:
  lore:
    - ' &7Простой меч.'
```

### item.amount

| Что | Значение |
|-----|----------|
| Тип | число (целое) |
| По умолчанию | `1` |
| Ограничение | от 1 до 64 |

Размер стака при выдаче предмета. Значения вне диапазона 1–64 обрезаются.

```yaml
item:
  amount: 3
```

### item.glowing

| Что | Значение |
|-----|----------|
| Тип | булево |
| По умолчанию | `false` |

Предмет переливается магическим светом (как зачарованный). Плагин добавляет скрытое зачарование «Нерушимость», чтобы свечение не давало бонуса и не отображалось в подсказке.

```yaml
item:
  glowing: true
```

### item.unbreakable

| Что | Значение |
|-----|----------|
| Тип | булево |
| По умолчанию | `false` |

Предмет нельзя сломать: у него нет полоски прочности.

```yaml
item:
  unbreakable: true
```

### item.enchantments

| Что | Значение |
|-----|----------|
| Тип | карта (имя зачарования → уровень) |
| По умолчанию | пусто |

Зачарования на предмете. Имя — как в Minecraft: `SHARPNESS`, `PROTECTION_ENVIRONMENTAL`, `FIRE_ASPECT`, `UNBREAKING`, `THORNS`, `SWEEPING_EDGE` и другие. Имя можно писать с дефисом вместо подчёркивания (`sharpness` = `SHARPNESS`).

Уровень должен быть больше нуля. Неизвестное зачарование — предупреждение в консоль, предмет при этом всё равно создаётся.

```yaml
item:
  enchantments:
    SHARPNESS: 4
    FIRE_ASPECT: 2
    UNBREAKING: 3
```

### item.item-flags

| Что | Значение |
|-----|----------|
| Тип | список строк |
| По умолчанию | пусто |

Флаги отображения. Позволяют спрятать служебные строки подсказки: атрибуты, прочность, зачарования и так далее.

| Флаг | Что прячет |
|------|-----------|
| `HIDE_ATTRIBUTES` | Строку с атрибутами |
| `HIDE_UNBREAKABLE` | Строку «Нерушимый» |
| `HIDE_ENCHANTS` | Список зачарований |
| `HIDE_ATTRIBUTION` | Подпись «Создано игроком» |
| `HIDE_DYE` | Информацию о покраске |
| `HIDE_POTION_EFFECTS` | Эффекты зелий в подсказке |

```yaml
item:
  item-flags:
    - HIDE_ATTRIBUTES
    - HIDE_UNBREAKABLE
```

### item.texture

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | нет |
| Работает только с | `PLAYER_HEAD` |

Текстура головы игрока. Принимается в трёх видах:

| Вид | Пример |
|-----|--------|
| Прямая ссылка | `https://example.com/skin.png` |
| Base64-строка текстуры | `eyJ0ZXh0dXJlcyI6...` |
| Хеш скина | `a1b2c3d4e5f6...` |

Если материал не `PLAYER_HEAD`, текстура просто игнорируется.

```yaml
item:
  type: PLAYER_HEAD
  texture: 'eyJ0ZXh0dXJlcyI6eyJTS0lOIjp7InVybCI6Imh0dHA6Ly90ZXh0dXJlcy5taW5lY3JhZnQubmV0L3RleHR1cmUvZmFlMTE5YTIzODJlZGE4NjRiMjQ0ZmE4YzUzYWMzZTU0NDE2MzEwM2VlNjY3OTVmMGNkNmM2NGY3YWJiOGNmMSJ9fX0='
```

### item.custom-model-data

| Что | Значение |
|-----|----------|
| Тип | число (целое) |
| По умолчанию | `-1` (не задано) |

Старый способ привязать модель к предмету: ресурс-пак смотрит на это число и подставляет свою текстуру. Используйте, если ресурс-пак сделан под `custom_model_data`.

Если одновременно задан `item-model` или `item-model-variant`, приоритет у них — `custom-model-data` в этом случае игнорируется.

```yaml
item:
  custom-model-data: 1001
```

### item.item-model

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | не задано |

Новый способ привязать модель (Minecraft 1.21.2+). Значение — путь к модели в ресурс-паке, обычно `minecraft:item/<название>` или имя вашей модели.

Модель при этом сохраняется и в служебных данных предмета, поэтому плагин может её найти.

```yaml
item:
  item-model: 'minecraft:item/netherite_sword'
```

### item.item-model-variant

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | не задано |

Дополнительная строка-вариант модели — используется для анимированных текстур и «состояний» модели.

Когда задан хотя бы один из ключей (`item-model`, `item-model-variant`), плагин записывает их в компонент модели как список строк. Если задан только `item-model-variant`, в список попадёт только вариант.

```yaml
item:
  item-model: 'minecraft:item/netherite_sword'
  item-model-variant: 'ember_blade_animated'
```

### item.attributes

| Что | Значение |
|-----|----------|
| Тип | карта (имя атрибута → число) |
| По умолчанию | пусто |

Постоянные бонусы к характеристикам игрока, пока предмет в слоте активации.

Допустимы два формата:

```yaml
item:
  attributes:
    GENERIC_ATTACK_DAMAGE: 8.0     # просто число
    GENERIC_MAX_HEALTH:
      value: 4.0                    # вложенный формат
```

Вложенный формат читается, но ключ `operation` сейчас не влияет на результат: атрибуты всегда прибавляются к базовому значению (операция `ADD_NUMBER`).

Имена атрибутов можно писать по-старому (`GENERIC_*`, `PLAYER_*`) и по-новому (`attack_damage`) — плагин понимает оба варианта. Неизвестное имя — предупреждение в консоль.

Полный список имён — в самом `config.yml` плагина в блоке `# ATTRIBUTE REFERENCE`.

```yaml
item:
  attributes:
    GENERIC_ATTACK_DAMAGE: 8.0
    GENERIC_MAX_HEALTH: 4.0
    GENERIC_MOVEMENT_SPEED: 0.2
```

### item.armor-set

| Что | Значение |
|-----|----------|
| Тип | строка |
| По умолчанию | нет |

ID набора брони. Предметы с одинаковым `armor-set` считаются частями одного комплекта; когда собраны все части, игрок получает бонус за полный набор.

Сам бонус описывается в `config.yml` плагина в секции `set-bonuses:`.

```yaml
item:
  armor-set: ember-knights
```

### item.has-set-bonus

| Что | Значение |
|-----|----------|
| Тип | булево |
| По умолчанию | `false` |

Участвует ли предмет в наборе. Если `armor-set` задан, а этот флаг — `false`, предмет всё равно считается частью комплекта (набор определяется ключом `armor-set`).

```yaml
item:
  armor-set: ember-knights
  has-set-bonus: true
```

Пример бонуса за набор в `config.yml`:

```yaml
set-bonuses:
  ember-knights:
    effects:
      - 'INCREASE_DAMAGE:3'
      - 'SPEED:2'
```

## Подстановки в lore

В описании предмета работают два плейсхолдера (подстановки). Плагин сам подставляет в них живые значения и обновляет описание у предмета в руке:

| Плейсхолдер | Что подставится | Пример |
|-------------|-----------------|--------|
| `%cooldown%` | Остаток кулдауна в секундах, одно знакок после запятой | `2.5` |
| `%uses%` | Остаток зарядов. Если зарядов нет — знак бесконечности `∞` | `18` |

```yaml
max-uses: 25
click-cooldown: 3000
lore:
  - ' &7Заряды: &b%uses%'
  - ' &7Перезарядка: &b%cooldown% &7сек.'
```

Если ключа `max-uses` нет, `%uses%` всегда показывает `∞`.

## Частые ошибки

| Симптом | Причина | Что делать |
|---------|---------|-----------|
| Предмет не появился в `/ci give <id>` | ID предмета — это верхний ключ файла, а не имя файла | Проверьте имя верхнего ключа |
| В консоли «Section 'item' not found» | Нет секции `item:` | Добавьте блок `item:` хотя бы с `type` |
| Эффекты не работают | Предмет не в слоте активации или в `effects` нет двоеточия | Проверьте `activation-slot` и формат `ЭФФЕКТ:УРОВЕНЬ` |
| Атрибуты не применяются | Блок `attributes:` лежит на верхнем уровне, а не внутри `item:` | Перенесите `attributes:` внутрь секции `item:` |
| Бонус за набор не выдаётся | `armor-set` лежит на верхнем уровне, а не внутри `item:` | Перенесите `armor-set:` внутрь секции `item:` |
| Описание не то | Верхний ключ `lore` перезаписал `item.lore` | Оставьте только один из них |
| Кулдаун не работает | Ключ называется `click-cooldown`, а не `cooldown` | Исправьте имя ключа |
| `trigger-actions` не работает | Ключ удалён в версии 1.328 | Перенесите действия в `triggers:` |
| Описание предмета не обновляется | У предмета нет `max-uses` или `click-cooldown` | Добавьте хотя бы одно из них |
| После правки ничего не изменилось | Не выполнен `/ci reload` | Выполните `/ci reload` и проверьте консоль |
| Предмет «пропал» из руки | Сработал `duration` или запрет мира | Уберите `duration` или исправьте списки миров |
