# Конфигурация

## Что ты узнаешь

- где лежит `config.yml` и что в нём вообще можно менять;
- полный справочник ключей: тип, значение по умолчанию, что делает ключ и когда его менять;
- почему `java-compilation` — это не просто переключатель, а вопрос безопасности;
- чего в `config.yml` больше нет (образцы не копируются, опция `extract-default-modules` удалена);
- как настроить бонус за полный комплект брони (`set-bonuses`) — с полным примером;
- какие имена атрибутов работают и что такое операции `ADD_NUMBER`, `MULTIPLY_BASE`, `MULTIPLY_TOTAL`;
- минимальный `config.yml`, с которым сервер работает.

## Где лежит config.yml

```text
plugins/DC-CustomItems/
├── config.yml        ← этот файл
├── items/            ← предметы, модули и сообщения
│   ├── messages.java
│   ├── runes.yml
│   └── vault/
├── data.db           ← база данных SQLite
├── backups/          ← резервные копии
├── compiled/         ← кэш скомпилированных .java-классов
└── logs/             ← логи плагина (если включён file-logging)
```

Открыть: `plugins/DC-CustomItems/config.yml`.

После правки — `/ci reload`. Исключение: **тип базы данных** (`database.type`) меняется только при полном перезапуске сервера.

## Что можно менять, а что нельзя

| Правило | Подробности |
|---------|--------------|
| `config.yml` — только настройки плагина | Предметы живут в `items/`, а не здесь |
| Ключи верхнего уровня, которых нет в справочнике | Считаются **предметами** — так работала старая установка. Новые предметы кладите в `items/` |
| Имя файла | `config.yml` — менять нельзя, плагин не найдёт настройки |
| Формат | YAML. Следите за отступами — важна вложенность секций |
| Комментарии (`#`) | Можно писать свои: они не мешают плагину |

После неудачной правки сервер не упадёт: если YAML невалиден, Bukkit сообщит об этом в консоли и загрузит пустую конфигурацию — плагин запустится с настройками по умолчанию.

## Справочник ключей

### Основные ключи

| Ключ | Тип | По умолчанию | Что делает | Когда менять |
|------|-----|--------------|------------|--------------|
| `java-compilation` | булево | `true` | Компилировать `.java`-файлы из `items/` прямо на сервере | Выключите (`false`), если доступ к файлам плагина есть у недоверенных людей. Подробнее — [Безопасность](#безопасность-java-compilation) |
| `debug-mode` | булево | `false` | Подробное логирование: показывает статистику кэша перечислений (`EnumCache`) после `/ci reload` | Включайте на время отладки. На рабочем сервере — выключено |
| `file-logging` | булево | `false` | Писать логи плагина в `plugins/DC-CustomItems/logs/latest.log` **вместо** консоли | Включите, если консоль забита сообщениями плагина. Подробнее — [Решение проблем](17-troubleshooting.md) |

### Резервные копии

| Ключ | Тип | По умолчанию | Что делает | Когда менять |
|------|-----|--------------|------------|--------------|
| `backup.on-reload` | булево | `true` | Создавать копию `items/` + `config.yml` + `data.db` перед каждым `/ci reload` | Выключите, если бэкапы не нужны или их слишком много |
| `backup.keep` | число | `5` | Сколько последних копий хранить. Минимум 1, лишние (самые старые) удаляются | Поставьте больше, если хотите длинную историю |

Копии лежат в `plugins/DC-CustomItems/backups/`. Подробнее — [База данных](12-database.md#резервные-копии).

### База данных

| Ключ | Тип | По умолчанию | Что делает | Когда менять |
|------|-----|--------------|------------|--------------|
| `database.type` | строка | `sqlite` | `sqlite` (файл `data.db`) или `mysql` | Когда нужен общий доступ к данным с нескольких серверов. **Требует перезапуска сервера** |
| `database.mysql.host` | строка | `127.0.0.1` | Адрес сервера MySQL | Если база на другой машине |
| `database.mysql.port` | число | `3306` | Порт MySQL | Если он нестандартный |
| `database.mysql.database` | строка | `dcustomitems` | Имя базы данных | Согласуйте с тем, что вы создали в MySQL |
| `database.mysql.username` | строка | `dcustomitems` | Пользователь MySQL | Создайте отдельного пользователя с правами только на свою базу |
| `database.mysql.password` | строка | `'change-me'` | Пароль пользователя | Замените заглушку. Лучше — через `DCI_MYSQL_PASSWORD` |
| `database.mysql.use-ssl` | булево | `false` | Шифрование соединения с MySQL | `true` для удалённой базы |
| `database.mysql.pool-size` | число | `5` | Сколько соединений держать открытыми | Больше — если много одновременных запросов |
| `database.mysql.connection-timeout-ms` | число | `5000` | Сколько мс ждать соединения перед ошибкой | Увеличьте для медленной сети |
| `database.mysql.leak-detection-ms` | число | `0` | Через сколько мс «зависшего» соединения писать предупреждение. `0` — выключено | Включите (например, `10000`) на время отладки MySQL |

Полное описание базы — на странице [База данных](12-database.md).

### Бонусы за наборы брони

| Ключ | Тип | По умолчанию | Что делает | Когда менять |
|------|-----|--------------|------------|--------------|
| `set-bonuses.<id>.effects` | список строк | — | Эффекты, которые даёт **полный** комплект брони с ID `<id>` | Когда создаёте свой набор брони |

Здесь `<id>` — тот же ID, что указан в `armor-set` у предметов. Пример — в разделе [set-bonuses](#set-bonuses-бонус-за-полный-комплект).

## Служебные ключи, которых нет в файле

Плагин читает ещё несколько ключей. В свежем `config.yml` их нет, но на старых серверах они могли остаться — и это нормально.

| Ключ | Тип | Значение по умолчанию | Что делает |
|------|-----|----------------------|------------|
| `update-available` | булево | `false` | Показывать при входе сообщение «доступна новая версия». Плагин сам этот ключ не выставляет |
| `latest-version` | строка | `unknown` | Номер версии для сообщения выше |
| `disable-worlds` | список строк | пусто | Миры, где плагин отключён (устаревший ключ) |
| `whitelist-blocks` | список строк | пусто | Список разрешённых блоков (устаревший ключ) |

Эти ключи входят в список служебных, поэтому плагин **не считает их предметами** и не ругается на них при загрузке.

## Безопасность: java-compilation

Это самый важный ключ в файле, поэтому читайте внимательно.

Когда `java-compilation: true`, плагин берёт каждый `.java`-файл из `items/` и **компилирует его на сервере**, а потом выполняет. Это значит:

> Тот, кто может положить файл в `plugins/DC-CustomItems/items/`, получает контроль над сервером.

| Что может сделать такой файл | Пример |
|------------------------------|--------|
| Выполнить любой код на сервере | Остановить сервер, прочитать чужие файлы |
| Уронить сервер | `System.exit(0)` — сервер выключится |
| Запустить внешние программы | `Runtime.getRuntime().exec(...)` |

Плагин не может этому помешать — это и есть смысл Java API. Но он **предупреждает** в консоли, если в файле встретились опасные вызовы:

```text
[JavaCompiler] ⚠ my-item.java contains a dangerous call 'System.exit' - check the file manually (java-compilation executes arbitrary code).
```

| Кто может писать в `items/` | Рекомендация |
|------------------------------|--------------|
| Только вы (администратор) | Оставьте `true` — это штатный режим |
| Другие сотрудники с ограниченным доступом | Подумайте: у них будет исполнение кода на сервере |
| Игроки, веб-панели, FTP с правом записи | Обязательно выключите: `java-compilation: false` |

Что происходит при `java-compilation: false`:

| Что | Результат |
|------|-----------|
| `.java`-файлы в `items/` | **Игнорируются** — не компилируются и не выполняются |
| YAML-предметы (`.yml`) | Работают как обычно |
| Модули на Java | Не загружаются |
| `items/messages.java` | Не загружается — остаются встроенные тексты плагина |

Выключая компиляцию, вы теряете Java API, но обезопашиваете сервер. Для публичного сервера с доступом к файлам у посторонних это обязательный шаг.

> Подробнее об угрозах — в [SECURITY.md](../SECURITY.md) репозитория.

## Чего больше нет в config.yml

Начиная с версии 1.332 в `config.yml` **нет** нескольких вещей, которые были раньше.

| Что изменилось | Как сейчас |
|----------------|------------|
| Образцы `EXAMPLE-*` | Не копируются в папку `items/` и не лежат внутри jar. Они живут в репозитории, в папке `samples/` |
| Опция `extract-default-modules` | **Удалена**. Ключ просто игнорируется, если остался в старом `config.yml` — его можно удалить |
| Класс `DefaultContentExtractor` | Удалён из кода вместе с опцией |

Как включить образец теперь:

```bash
# 1. Скопировать нужный файл или папку из репозитория (samples/)
cp samples/EXAMPLE-runes.yml plugins/DC-CustomItems/items/runes.yml
cp -r samples/EXAMPLE-vault plugins/DC-CustomItems/items/vault

# 2. Убрать префикс EXAMPLE- (если он остался в имени)
#    EXAMPLE-runes.yml -> runes.yml
#    EXAMPLE-vault/    -> vault/

# 3. Перезагрузить
/ci reload
```

Что при этом создаёт плагин при установке:

| Файл | Что это |
|------|---------|
| `plugins/DC-CustomItems/items/messages.java` | **Единственный** файл, который плагин создаёт сам. Все тексты плагина — здесь |

То есть чистая установка выглядит так:

```text
plugins/DC-CustomItems/
├── config.yml
├── items/
│   └── messages.java
└── data.db
```

Файлы с префиксом `EXAMPLE-` в `items/` плагин **всегда игнорирует** — и в YAML, и в Java.

## set-bonuses: бонус за полный комплект

**Сет-бонус** — дополнительные эффекты, которые игрок получает, когда собрал **все четыре** части комплекта брони.

Механика работает так:

1. Каждый предмет брони указывает `armor-set: <id>` — имя комплекта.
2. Плагин считает, сколько частей с таким ID надето на игроке.
3. Если надеты все 4 (шапка, нагрудник, штаны, ботинки) — выдаются эффекты из `set-bonuses.<id>.effects` в `config.yml`.
4. Снимаете одну часть — бонус пропадает.

### Полный пример

Шаг 1. Четыре предмета брони в `items/dark-lord.yml`. Важно: `armor-set` лежит **внутри секции `item:`** — иначе плагин его не увидит.

```yaml
dark-lord-helmet:
  type: ARMOR
  activation-slot: HEAD
  item:
    type: NETHERITE_HELMET
    title: '&5[✪] &dШлем &5Тёмного Властелина'
    glowing: true
    unbreakable: true
    armor-set: dark-lord
    has-set-bonus: true
  effects:
    - 'DAMAGE_RESISTANCE:1'

dark-lord-chestplate:
  type: ARMOR
  activation-slot: CHEST
  item:
    type: NETHERITE_CHESTPLATE
    title: '&5[✪] &dНагрудник &5Тёмного Властелина'
    glowing: true
    unbreakable: true
    armor-set: dark-lord
    has-set-bonus: true
  effects:
    - 'DAMAGE_RESISTANCE:2'

dark-lord-leggings:
  type: ARMOR
  activation-slot: LEGS
  item:
    type: NETHERITE_LEGGINGS
    title: '&5[✪] &dПоножи &5Тёмного Властелина'
    glowing: true
    unbreakable: true
    armor-set: dark-lord
    has-set-bonus: true
  effects:
    - 'DAMAGE_RESISTANCE:1'

dark-lord-boots:
  type: ARMOR
  activation-slot: FEET
  item:
    type: NETHERITE_BOOTS
    title: '&5[✪] &dБотинки &5Тёмного Властелина'
    glowing: true
    unbreakable: true
    armor-set: dark-lord
    has-set-bonus: true
  effects:
    - 'DAMAGE_RESISTANCE:1'
```

Шаг 2. Бонус за полный комплект — в `config.yml`:

```yaml
set-bonuses:
  dark-lord:
    effects:
      - 'INCREASE_DAMAGE:3'
      - 'SPEED:2'
      - 'REGENERATION:2'
```

Шаг 3. `/ci reload` и проверка: наденьте все четыре части.

### Формат эффектов

Каждый эффект — строка `ИМЯ:УРОВЕНЬ`.

| Часть | Что это |
|-------|---------|
| `ИМЯ` | Имя эффекта зелия. `INCREASE_DAMAGE` — сила, `SPEED` — скорость, `REGENERATION` — регенерация |
| `УРОВЕНЬ` | Уровень эффекта, начиная с 1. `SPEED:2` — скорость II |

| Что происходит | Результат |
|----------------|-----------|
| Эффекты нескольких предметов | Берётся **максимальный** уровень, а не сумма. `SPEED:1` + `SPEED:2` = скорость II |
| Бонус за набор | Тоже объединяется по максимуму с эффектами предметов |
| Неизвестное имя эффекта | В лог уходит предупреждение `Unknown effect: <ИМЯ>` |
| В `set-bonuses` нет сета с таким ID | В лог уходит предупреждение `Set bonuses for '<id>' were not found in the config!` |

Несколько наборов — это несколько блоков в одной секции:

```yaml
set-bonuses:
  dark-lord:
    effects:
      - 'INCREASE_DAMAGE:3'
      - 'SPEED:2'
  ember-knights:
    effects:
      - 'FIRE_RESISTANCE:1'
      - 'JUMP:2'
```

## Справочник атрибутов

**Атрибут** — это числовая характеристика игрока: скорость, урон, здоровье, сопротивление. Кастомный предмет может добавлять и менять их.

Атрибуты задаются в секции `item:` предмета:

```yaml
my-blade:
  type: TOOL
  activation-slot: HAND
  item:
    type: DIAMOND_SWORD
    title: '&bКлинок Бури'
    attributes:
      GENERIC_ATTACK_DAMAGE: 4.0
      attack_speed: 2.0
      GENERIC_KNOCKBACK_RESISTANCE: 0.1
```

### Какие имена работают

Плагин понимает три вида имён. Регистр не важен: `attack_damage`, `ATTACK_DAMAGE` и `Attack_Damage` — одно и то же.

| Вид имени | Пример | Когда использовать |
|------------|--------|--------------------|
| Современные имена | `attack_damage`, `max_health`, `movement_speed` | Рекомендуемый вариант — коротко и актуально |
| Старые имена (legacy) | `GENERIC_ATTACK_DAMAGE`, `PLAYER_BLOCK_INTERACTION_RANGE` | В готовых примерах плагина и старых сборках |
| Реестровые ключи | `minecraft:attack_damage` | Когда нужно указать namespace явно |

Старые префиксы, которые понимаются: `GENERIC_`, `PLAYER_`, `ZOMBIE_`, `HORSE_`, `LLAMA_`, `MINECRAFT_`, `BOAT_`. Плагин отбрасывает префикс и ищет атрибут по оставшейся части.

Если атрибут не найден, в лог уходит предупреждение:

```text
Unknown attribute: GENERIC_NOT_REAL for item: my-blade
```

### Операции

**Операция** — это правило, как число из YAML складывается с базовым значением атрибута.

| Операция | Что делает | Пример |
|----------|------------|--------|
| `ADD_NUMBER` | Прибавить число к базовому значению | `+4.0` к урону |
| `MULTIPLY_BASE` | Умножить базовое значение | базовый урон 1.0 × 2 = 2.0 |
| `MULTIPLY_TOTAL` | Умножить итоговое значение | (база + бонусы) × множитель |

Практика: в YAML вы пишете **только число** — операция выбирается автоматически. Например:

```yaml
attributes:
  GENERIC_ATTACK_DAMAGE: 4.0     # +4.0 к урону (ADD_NUMBER)
```

> Важно: сейчас плагин применяет атрибуты операцией `ADD_NUMBER` — то есть всегда прибавляет указанное число. Операции `MULTIPLY_BASE` и `MULTIPLY_TOTAL` описаны в справочнике, но в YAML-формате выбрать их нельзя: в `config.yml` есть только ключ `value`, без поля операции. Если вам нужен множитель — считайте его сами и задайте готовым числом.

| `GENERIC_ATTACK_KNOCKBACK` | Откидывание при атаке |
| `GENERIC_ATTACK_SPEED` | Скорость атаки |
| `GENERIC_ARMOR` | Защита |
| `GENERIC_ARMOR_TOUGHNESS` | Прочность брони |
| `GENERIC_FALL_DAMAGE_MULTIPLIER` | Множитель урона от падения |

| `GENERIC_EXPLOSION_KNOCKBACK_RESISTANCE` | Сопротивление откидыванию взрывами |
| `GENERIC_MOVEMENT_EFFICIENCY` | Эффективность передвижения |
| `GENERIC_OXYGEN_BONUS` | Запас воздуха |
| `GENERIC_WATER_MOVEMENT_EFFICIENCY` | Эффективность передвижения в воде |
| `PLAYER_BLOCK_INTERACTION_RANGE` | Дальность взаимодействия с блоками |
| `PLAYER_ENTITY_INTERACTION_RANGE` | Дальность взаимодействия с существами |
| `PLAYER_BLOCK_BREAK_SPEED` | Скорость добычи блоков |
| `PLAYER_MINING_EFFICIENCY` | Эффективность добычи |
| `PLAYER_SNEAKING_SPEED` | Скорость в приседе |
| `PLAYER_SUBMERGED_MINING_SPEED` | Скорость добычи под водой |
| `PLAYER_SWEEPING_DAMAGE_RATIO` | Доля урона от широкой атаки |
| `ZOMBIE_SPAWN_REINFORCEMENTS` | Подкрепления зомби |

Где применяются атрибуты:

| Ситуация | Результат |
|----------|-----------|
| Предмет в слоте активации | Атрибуты действуют |
| Предмет не в слоте активации | Атрибуты не действуют |
| Несколько предметов с одним атрибутом | Значения **складываются** |
| Предмет сняли | Атрибут убирается |

## Минимальный config.yml

Если вам нужно только «рабочее и понятное» начало, вот минимальный файл. Все остальные ключи плагин подставит сам.

```yaml
# ==========================================
# DC-CustomItems — минимальная настройка
# ==========================================

# Компиляция .java-файлов из items/. Выключите, если файлы плагина
# доступы недоверенным людям.
java-compilation: true

# Подробные логи — только для отладки.
debug-mode: false

# Логи плагина в отдельный файл вместо консоли.
file-logging: false

# Копия items/ + config.yml + data.db перед /ci reload.
backup:
  on-reload: true
  keep: 5

# Локальная база в файле data.db.
database:
  type: sqlite
  mysql:
    host: 127.0.0.1
    port: 3306
    database: dcustomitems
    username: dcustomitems
    password: 'change-me'
    use-ssl: false
    pool-size: 5
    connection-timeout-ms: 5000
    leak-detection-ms: 0

# Бонусы за полные комплекты брони.
set-bonuses: {}
```

> Даже в «минимальном» файле оставьте секцию `database.mysql` — она не мешает, пока `database.type: sqlite`, но пригодится, когда перейдёте на MySQL. Секцию `set-bonuses` можно удалить целиком, если комплектов с бонусами у вас нет.

## Подводные камни

| Проблема | Причина | Что делать |
|----------|---------|------------|
| Изменения не применились | Забыли `/ci reload` | Выполните `/ci reload`. Для `database.type` нужен **перезапуск** |
| `Set bonuses for 'x' were not found in the config!` | В `config.yml` нет секции `set-bonuses.x` | Добавьте её. ID должен совпадать с `armor-set` у предметов |
| Атрибут не применяется | `attributes:` лежит на верхнем уровне предмета, а не внутри `item:` | Перенесите блок внутрь секции `item:` |
| Предмет не загрузился, в лог `Section 'item' not found` | Нет секции `item:` | Добавьте `item:` с `type:` материала |
| Лог плагина пропал из консоли | Включён `file-logging: true` | Смотрите `plugins/DC-CustomItems/logs/latest.log` или выключите ключ |
| Плагин ругается на незнакомый ключ | Ключ верхнего уровня, которого нет в справочнике, плагин считает **предметом** | Уберите ключ или оформите его как предмет (с секцией `item:`) |
| `.java`-файлы перестали работать | `java-compilation: false` | Включите обратно, если сервером управляете только вы |
| `extract-default-modules` в файле остался | Ключ удалён в 1.332 | Удалите строку — на работу не влияет |
