| Что вы видите | Скорее всего | Раздел |

| Триггер `on_kill` не сработал | Опечатка в имени триггера или сработал кулдаун | [Триггер не срабатывает](#триггер-не-срабатывает) |

| `/mymodule` — «Unknown command» | Класс не скомпилировался или не extends `CustomCommand` | [Команда на Java не появилась](#команда-на-java-не-появилась) |
| `%player_name%` в чате как обычный текст | Не установлен PlaceholderAPI | [Плейсхолдеры](#плейсхолдеры-показываются-буквально) |

| Предмет пропал из инвентаря | Истёк срок, кончились заряды или запрещён в мире | [Предмет исчез](#предмет-исчез) |

## Плагин не включается

### Симптом

В консоли при старте сервера:

```text
[Server] DC-CustomItems v1.333.0 could not be loaded (Unsupported API version)
```

или

```text
[Server] Could not load plugin 'DC-CustomItems.jar' in folder 'plugins'
```

### Причины и решения

| Сообщение | Причина | Решение |
|-----------|---------|---------|
| `Unsupported API version` | Плагин требует Minecraft 1.21 или новее (`api-version: '1.21'` в `plugin.yml`) | Обновите сервер до 1.21+ |
| `Invalid plugin.yml` | Повреждённый jar — файл докачался не полностью | Скачайте jar заново с [GitHub Releases](https://github.com/animesao/dcustomitems/releases) |
| `UnsupportedClassVersionError` | На сервере старая Java | Нужна Java 21 — см. ниже |
| `NoSuchMethodError` / `NoClassDefFoundError` | Несовместимость версий Paper и плагина | Обновите Paper или возьмите подходящую версию плагина |
| Плагин включился и сразу выключился | Ошибка при инициализации | Смотрите строки выше в консоли — плагин пишет точную причину (`Error enabling plugin: ...`) |

### Как проверить версию

```bash
# Версия плагина
java -jar plugins/DC-CustomItems.jar --version   # не у всех сборок работает

# Надёжнее — посмотреть в plugin.yml внутри jar
unzip -p plugins/DC-CustomItems.jar plugin.yml
```

Требования к серверу:

| Параметр | Значение |
|----------|----------|
| Minecraft | 1.21 и новее (разрабатывалось под 1.21.8) |
| Сервер | Paper или Spigot |
| Java | 21 |

## JavaCompiler not found

### Симптом

В консоли:

```text
[JavaCompiler] JavaCompiler not found! JDK required.
```

Java-предметы и Java-модули при этом не загружаются. YAML-предметы работают.

### Причина

Плагин компилирует `.java`-файлы **на самом сервере**, используя стандартный компилятор Java из JDK (`javax.tools.ToolProvider`). Установленный на сервере **JRE** (без компилятора) этого метода не содержит — и метод возвращает `null`.

| Установлено | Есть ли компилятор | Java-предметы |
|-------------|--------------------|--------------|
| JRE | Нет | Не работают |
| JDK | Есть | Работают |

### Решение

Поставьте на сервер **JDK 21**, а не JRE. Например, Temurin:

```bash
# Linux, проверка текущей версии
java -version

# Установка JDK 21 (Debian/Ubuntu)
sudo apt install openjdk-21-jdk

# Установка JDK 21 (RHEL/CentOS/Alma)
sudo dnf install java-21-openjdk-devel
```

Проверка после установки:

```bash
# Должно быть "openjdk version" и "OpenJDK Runtime Environment"
java -version

# Должно найти компилятор
javac -version
```

Перезапустите сервер: переменная `PATH` обновляется только при новом запуске.

### Альтернатива

Если JDK ставить нельзя (например, хостинг без прав), выключите компиляцию и пишите предметы на YAML:

```yaml
# config.yml
java-compilation: false
```

Подробнее о безопасности — в [Конфигурация](14-configuration.md#безопасность-java-compilation).

## Файл .java не компилируется

### Симптом

В консоли — строка с ошибкой компилятора:

```text
[JavaCompiler] ❌ my-item.java:12 - cannot find symbol
[JavaCompiler] ❌ my-item.java:8 - ';' expected
[JavaCompiler] ❌ my-item.java:20 - class, interface, enum, or record expected
```

После этого предмет или команда **не появляются** — файл просто не был скомпилирован.

### Как читать ошибку

Формат всегда одинаковый:

```text
[JavaCompiler] ❌ <имя файла>:<строка> - <текст ошибки>
```

| Часть | Что это |
|-------|--------|
| Имя файла | Какой файл не собрался |
| Номер строки | Строка в файле, где ошибка |
| Текст | Что именно не так (сообщение `javac`) |

### Типичные причины

| Сообщение | Причина | Что делать |
|-----------|---------|------------|
| `cannot find symbol` | Нет класса, метода или **поля**, которое вы используете | Проверьте имя. Частая ошибка: в `messages.java` написано поле, которого нет в `MessagesConfig` (например, `CI_HELP_GIVE`) |
| `';' expected` | Пропущена `;` или потеряна скобка | Пересчитайте скобки и точки с запятой |
| `class, interface, enum, or record expected` | Класс не на верхнем уровне или перед ним лишний текст | В файле должен быть ровно один `public class` |
| `does not exist` (пакет) | Неверный `import` | Проверьте путь: `me.dcplugin.dcustomitems.api.AbstractCustomItem` |
| `cannot find symbol: method ...` | Метода нет в API | Сверьтесь со [Справочником API](18-api-reference.md) |
| `duplicate class` | Два файла с одинаковым именем класса | Переименуйте один из файлов |
| `class X is public, should be declared in a file named X.java` | Имя публичного класса не совпадает с именем файла | Переименуйте файл так, чтобы он совпадал с классом |

### Проверка до сервера

Скомпилируйте файл локально, чтобы увидеть ошибки с подсветкой:

```bash
javac -cp "путь/к/DC-CustomItems.jar" my-item.java
```

### Что ещё стоит знать

| Правило | Подробности |
|---------|--------------|
| Имя класса | Обычно совпадает с именем файла. Плагин переименовывает классы сам, но для читаемости держите имена одинаковыми |
| `package` | Своё объявление `package` в файле **удаляется** плагином (иначе было бы два `package`). Можно писать, можно не писать |
| Импорты | Плагин сам добавляет `AbstractCustomItem`, `ItemAPI`, `CustomCommand`, `CustomPlaceholder`, если их нет |
| Опасные вызовы | `System.exit`, `Runtime.getRuntime().exec`, `ProcessBuilder`, `.setAccessible(` — плагин пишет предупреждение, но **не запрещает** |
| Лимиты | Не больше 300 `.java`-файлов и не больше 512 КБ на файл |
| Папки `EXAMPLE-*`, `EXAMPLES`, `_template` | Не компилируются — это примеры |

## Предмет не распознаётся

### Симптом

- `/give <id>` отвечает, что предмет не найден;
- в логе `Section 'item' not found for item: <id>`;
- предмет в инвентаре есть, но ничего не происходит.

### Причины

| Причина | Как проверить | Решение |
|---------|---------------|---------|
| Неправильное расширение файла | Файл называется `runes.yaml` — это нормально, а вот `runes.txt` — нет | Расширение должно быть `.yml` или `.yaml` |
| Файл не в папке `items/` | Файл лежит в корне папки плагина | Перенесите в `plugins/DC-CustomItems/items/` |
| Префикс `EXAMPLE-` | Файл называется `EXAMPLE-runes.yml` | Такие файлы **всегда** игнорируются. Переименуйте, убрав префикс |
| ID предмета — это не имя файла | В файле `runes.yml` предмет называется `fire_rune`, а вы ищете `runes` | ID = **верхний ключ** в YAML |
| Нет секции `item:` | В предмете нет блока `item:` с `type:` | Добавьте `item:` и `type: DIAMOND_SWORD` |
| Неизвестный материал | `type: DIAMONDSWORD` (опечатка) | В лог пишется `Unknown material: ...`. Исправьте имя материала |
| Предмет не перезагружен | Изменили файл, но не сделали `/ci reload` | `/ci reload` |
| Материал — `AIR` | `type: AIR` | В лог пишется `Invalid (AIR) material` |

### Как посмотреть, что загрузилось

```bash
# Дамп предмета: тип, слот, заряды, кулдаун, рецепты, служебные данные
/ci debug <id>

# Проверка рецептов
/ci validate
```

Команда `/ci debug` требует права `dcustomitems.reload`.

## Бонус за набор и атрибуты не работают

### Симптом

Броня надета, а бонус за комплект не даётся. Или атрибуты не меняют характеристики.

### Причины

| Причина | Как выглядит | Решение |
|---------|--------------|---------|
| `armor-set` или `attributes` лежат **на верхнем уровне** предмета | В YAML они рядом с `item:`, а не внутри | Перенесите внутрь секции `item:` — плагин читает их **только** оттуда |
| Нет всех 4 частей | Надеты 3 из 4 | Бонус даётся только за полный комплект: шлем + нагрудник + штаны + ботинки |
| Не совпадает ID сета | В предмете `armor-set: shadow`, в конфиге `set-bonuses: dark-lord` | ID должны совпадать символ в символ |
| Нет секции `set-bonuses` в конфиге | В лог: `Set bonuses for 'x' were not found in the config!` | Добавьте `set-bonuses.x.effects` в `config.yml` |
| Предмет не в слоте активации | Шлем в руке | `activation-slot` должен совпадать с тем слотом, где предмет надет |
| Неизвестное имя атрибута | В лог: `Unknown attribute: GENERIC_FOO for item: x` | Проверьте имя по [справочнику атрибутов](14-configuration.md#справочник-атрибутов) |

### Правильно

```yaml
dark-lord-helmet:
  type: ARMOR
  activation-slot: HEAD
  item:
    type: NETHERITE_HELMET
    title: '&5Шлем Тёмного Властелина'
    armor-set: dark-lord        # ← внутри item:
    attributes:                 # ← внутри item:
      GENERIC_ARMOR: 3.0
```

### Неправильно

```yaml
dark-lord-helmet:
  type: ARMOR
  activation-slot: HEAD
  armor-set: dark-lord          # ← плагин это проигнорирует
  attributes:                   # ← плагин это проигнорирует
    GENERIC_ARMOR: 3.0
  item:
    type: NETHERITE_HELMET
```

## Эффекты не применяются

### Симптом

Зелье (`SPEED`, `STRENGTH`) не появляется, хотя предмет надет.

### Причины

| Причина | Подробности | Решение |
|---------|-------------|---------|
| Предмет не в слоте активации | Постоянные эффекты и атрибуты работают **только** в слоте активации | Проверьте `activation-slot`. Для руки — `HAND`, для второй руки — `OFFHAND`, для брони — `HEAD`/`CHEST`/`LEGS`/`FEET` |
| Неправильный формат эффекта | Нужно `ИМЯ:УРОВЕНЬ`, например `SPEED:2` | Исправьте формат. Без двоеточия эффект не распарсится |
| Неизвестное имя эффекта | В лог: `Unknown effect: MYEFFECT` | Используйте имя из списка эффектов зелий Minecraft |
| Уровень написан не как число | `SPEED:два` | Только число, начиная с 1 |
| Эффект перебит другим предметом | Уровни **не складываются** — берётся максимум | Это ожидаемое поведение |
| Предмет типа `CONSUMABLE` | Расходник применяет эффекты **один раз** при клике, а не постоянно | Оставьте предмет типа `TOOL`/`ARMOR`/`RUNE`, если нужен постоянный эффект |

Отдельно: если эффект не виден сразу, проверьте, не снимает ли его другой плагин (например, другой плагин с эффектами зелий).

## Действие не выполняется

### Симптом

Кликнули по предмету — звука, частиц, сообщения, телепорта нет.

### Проверьте по порядку

**1. Формат.** Действие — это строка `тип:значение`, где тип отделяется двоеточием.

```yaml
right-click-actions:
  - 'heal:10'                  # правильно
  - 'message:&aГотово!'        # правильно
  - 'teleport:~0:5:~0'         # правильно
```

| Что написали | Что будет | Как надо |
|--------------|-----------|----------|
| `heal` | Не хватает значения | `heal:10` |
| `HEAL:10` | Работает — регистр не важен | — |
| `damage-mobs:5:3` | Работает — дефис и подчёркивание равнозначны | — |
| `НеизвестноеДействие:1` | Игнорируется, в лог ничего не пишется | Проверьте список действий |

**2. Регистр и опечатки.** Тип действия приводится к нижнему регистру, дефисы заменяются подчёркиваниями. `damage-mobs` и `damage_mobs` — одно и то же. Но `damageMobs` — уже другое (не найдётся).

**3. Тип предмета `CONSUMABLE`.** Расходник работает иначе: при клике он **только** применяет эффекты и исчезает. Действия (`left-click-actions`, `right-click-actions`) для него **не выполняются**.

```yaml
potion:
  type: CONSUMABLE        # ← действия не выполняются
  effects:
    - 'REGENERATION:5'
```

Если хотите и эффект, и действие — сделайте предмет типа `TOOL` и счётчик зарядов `max-uses`.

**4. Право.** Если у предмета задан `permission:` и у игрока нет этого права, клик отменяется **до** выполнения действий. Игрок увидит сообщение о недостатке прав.

**5. Кулдаун.** Если предмет на кулдауне (`click-cooldown`), клик игнорируется и показывается сообщение о кулдауне.

**6. Слот.** Действия выполняются при клике предметом **в руке** (или во второй руке). Предмет, лежащий в сундуке или в слоте брони, действий не запускает.

Полный список действий с форматом — на странице [Действия](05-actions.md).

## Триггер не срабатывает

### Симптом

Убили моба, но `on_kill` не сработал. Или не сработал `on_equip`, `on_jump`, `on_click_right`.

### Проверьте по порядку

**1. Имя триггера пишется точно.** Регистр важен, лишние пробелы — тоже.

| Имя триггера | Когда срабатывает |
|--------------|------------------|
| `on_click_left` | Клик левой кнопкой мыши |
| `on_click_right` | Клик правой кнопкой мыши |
| `on_equip` | Предмет занял слот активации |
| `on_unequip` | Предмет покинул слот активации |
| `on_kill` | Игрок убил игрока |
| `on_death` | Игрок умер |
| `on_damage_dealt` | Игрок нанёс урон |
| `on_damage_taken` | Игрок получил урон |
| `on_jump` | Игрок прыгнул |
| `on_sprint` | Игрок начал бежать |
| `on_pickup` | Игрок подобрал предмет |
| `on_drop` | Игрок выбросил предмет |

**2. Секция `triggers:`, а не `trigger-actions:`.** Старый ключ `trigger-actions` удалён в 1.328. Если он остался в файле, плагин напишет в лог:

```text
[LOAD] 'trigger-actions' was removed in 1.328 - use the 'triggers:' section instead. The key is ignored.
```

Правильно:

```yaml
triggers:
  on_kill:
    - 'heal:5'
  on_click_right:
    - 'particle:FLAME:20'
```

**3. Где лежит предмет.** Триггеры ищутся в **руках и броне** игрока. Предмет в сундуке или в отдельном слоте инвентаря триггеры не запускает. При этом **слот активации на триггеры не влияет** — триггер сработает, даже если предмет лежит не в своём слоте.

**4. Кулдаун.** Если предмет на кулдауне, повторное срабатывание блокируется. Кулдаун задаётся:

| Откуда | Как |
|--------|-----|
| `click-cooldown` предмета | Общий кулдаун клика в миллисекундах |
| Псевдо-действие `cooldown:МС` в самом триггере | Свой кулдаун конкретного триггера |

```yaml
triggers:
  on_kill:
    - 'cooldown:10000'     # этот триггер — раз в 10 секунд
    - 'heal:5'
```

**5. Событие отменено другим плагином.** Плагин отдаёт наружу Bukkit-события — если третий плагин отменил событие, триггер не выполнится.

## Команда /ci не работает

### Симптом

```text
[DC-CustomItems] No permission!
```

или команда вообще не находится.

### Причины

| Причина | Решение |
|---------|---------|
| Нет права `dcustomitems.reload` | Выдайте право или сделайте игрока оператором (`/op Steve`) |
| Плагин не загрузился | Смотрите [Плагин не включается](#плагин-не-включается) |
| Команда перехвачена другим плагином | Проверьте, не зарегистрировал ли кто-то команду `ci` или `customitems` |

Команда и её алиасы:

| Команда | Что это |
|---------|---------|
| `/ci` | То же самое, что `/customitems` |
| `/customitems` | Полное имя |

Право `dcustomitems.reload` объявлено с `default: op` — то есть у операторов оно есть сразу, а обычным игрокам нужно выдавать отдельно.

## Команда на Java не появилась

### Симптом

```text
Unknown command: /mymodule
```

или после `/ci reload` в логе нет строки `[API] Registered command: /mymodule`.

### Проверьте по порядку

**1. Класс должен наследоваться от `CustomCommand`.** Плагин определяет тип файла по этой строке:

```java
public class MyModule extends CustomCommand {   // ← именно так
    public MyModule() {
        super("mymodule", "Описание", "/mymodule", "myplugin.mymodule");
    }

    @Override
    public boolean execute(CommandSender sender, String[] args) {
        sender.sendMessage("Работает!");
        return true;
    }
}
```

| Что написано | Что будет |
|--------------|-----------|
| `extends CustomCommand` | Команда |
| `extends AbstractCustomItem` | Предмет |
| `extends CustomPlaceholder` | Плейсхолдер |
| `extends Module` | Модуль |
| Ничего не наследует | Файл скомпилируется, но **ничем не станет** (utility-класс) |

**2. Файл должен быть в `items/`.** Вложенные папки тоже работают:

```text
plugins/DC-CustomItems/items/my-module.java
plugins/DC-CustomItems/items/my-module/my-module.java
```

**3. Сделайте `/ci reload`.** Команды регистрируются при загрузке Java API — без перезагрузки новый файл не подхватится.

**4. Посмотрите лог.** При загрузке плагин пишет:

```text
[JavaCompiler] Found 3 .java files
[JavaCompiler] Compiled: 2, Skipped: 1 (120ms)
[API] Registered command: /mymodule
```

Если строки `Registered command` нет — файл не скомпилировался или не распознан как команда.

**5. Имя команды.** Оно берётся из конструктора `super(...)`, а не из имени файла. Проверьте, что оно в нижнем регистре (плагин приводит сам) и не совпадает с другой командой.

## Плейсхолдеры показываются буквально

### Симптом

В чате, на табличке или в меню вместо значения — сам текст:

```text
%player_name%
%dci_health%
```

### Причина

**PlaceholderAPI не установлен** (или не установлен нужный expansion — «расширение»).

Плагин подставляет плейсхолдеры через PlaceholderAPI. Если PlaceholderAPI нет, подстановка не происходит, и текст остаётся как есть. Свои плейсхолдеры у плагина начинаются с `%dci_` — например `%dci_player%`, `%dci_health%`, `%dci_version%`.

### Решение

1. Установите [PlaceholderAPI](https://www.spigotmc.org/resources/placeholderapi.6245/).
2. Перезапустите сервер.
3. Если плейсхолдер не поддерживается — доустановите нужное расширение. Например, `%player_name%` — это расширение **Player**, `%vault_eco_balance%` — **Vault**, `%luckperms_prefix%` — **LuckPerms**.

Проверка в чате:

```text
/papi parse %player_name%
/papi parse %dci_version%
```

Полный список плейсхолдеров плагина — на странице [Плейсхолдеры](09-placeholders.md).

> Свои плейсхолдеры (на Java) работают и без PlaceholderAPI — они просто не подставляются в тексты других плагинов.

## Сообщения не изменились после правки messages.java

### Симптом

Вы поменяли `plugins/DC-CustomItems/items/messages.java`, сделали `/ci reload`, а тексты остались прежними.

### Проверьте по порядку

**1. Сделайте `/ci reload`.** Файл читается при загрузке Java API.

**2. Файл должен скомпилироваться.** Если в нём ошибка, плагин продолжит работать со **старыми** текстами. В консоли будет ошибка компилятора:

```text
[JavaCompiler] ❌ messages.java:42 - cannot find symbol
```

Самая частая причина — **несуществующее поле**. Например, в `MessagesConfig` нет поля `CI_HELP_GIVE`, но в вашем файле оно есть. Плагин не знает про эту опечатку — он просто не может собрать класс.

Как узнать правильные имена полей:

| Что нужно | Где смотреть |
|-----------|--------------|
| Список полей `MessagesConfig` | Файл `src/main/java/me/dcplugin/dcustomitems/api/config/MessagesConfig.java` |
| Готовый рабочий файл | `plugins/DC-CustomItems/items/messages.java` (тот, что создал плагин) |
| Пути сообщений (например `items.expired`) | Там же, в блоке `BUILT_IN` |

**3. Проверьте приоритет.** Текст берётся из первого источника, который что-то вернул:

| Приоритет | Источник |
|-----------|----------|
| 1 | Ваш `items/messages.java` (через `MessagesConfig.set("путь", "текст")`) |
| 2 | Текст, зарегистрированный модулем (`registerMessage`) |
| 3 | Встроенный текст плагина |
| 4 | Значение по умолчанию из кода |

Если модуль зарегистрировал свой текст по тому же пути — он победит ваш.

**4. Проверьте путь.** Для встроенных сообщений пути такие:

| Путь | Какой текст |
|------|-------------|
| `items.expired` | «Предмет истёк» |
| `items.world-blocked` | «Предмет запрещён в этом мире» |
| `items.no-permission` | «Нет прав на использование предмета» |
| `items.uses-depleted` | «Предмет израсходован» |
| `commands.no-permission` | «Нет прав» для команд |
| `commands.not-found` | «Команда не найдена» |
| `ci.reload.success` | «Перезагружено!» |
| `update.title` | Заголовок уведомления о версии |

Свои пути работают так же: задайте `MessagesConfig.set("my.text", "Привет")` — и модуль прочитает его через `getMessage("my.text", ...)`.

**5. Включите `debug-mode: true`** и сделайте `/ci reload` — в консоли появится статистика загрузки.

## База данных не подключается

### Симптом

```text
[DC-CustomItems] MySQL connection error: Communications link failure
```

или

```text
MySQL connection error: Access denied for user 'dcustomitems'@'localhost' (using password: YES)
```

или

```text
[DC-CustomItems] SQLite connection error: ...
```

### Разбор по сообщениям

| Сообщение | Причина | Решение |
|-----------|---------|---------|
| `Access denied for user` | Неверный пароль или у пользователя нет прав на базу | Проверьте `username`/`password`, пересоздайте пользователя с `GRANT` |
| `Unknown database 'dcustomitems'` | База не создана | Создайте её: `CREATE DATABASE dcustomitems;` |
| `Communications link failure` | Неверный хост/порт, или MySQL не слушает этот адрес | Проверьте `host`, `port`, firewall, `bind-address` в MySQL |
| `Connection refused` | MySQL не запущен или слушает только localhost | Запустите MySQL, проверьте адрес |
| `Public Key Retrieval is not allowed` | Несовместимая аутентификация MySQL 8 | Добавьте к JDBC-URL параметр `allowPublicKeyRetrieval=true` — скажите разработчику, если это нужно |

### Проверка доступа вручную

```bash
mysql -h 127.0.0.1 -P 3306 -u dcustomitems -p dcustomitems
```

Если подключение проходит — проблема в настройках плагина, а не в MySQL.

### Частая ошибка: забыли перезапустить сервер

Тип базы читается **только при старте**. После правки `database.type` нужен полный перезапуск, а не `/ci reload`:

```text
Database connected: MySQL (127.0.0.1:3306/dcustomitems)   ← успех
Database connected: SQLite (.../data.db)                   ← SQLite
```

### Переменная окружения `DCI_MYSQL_PASSWORD`

Если вы задаёте пароль через `DCI_MYSQL_PASSWORD`, проверьте:

| Проверка | Как |
|----------|-----|
| Переменная видна серверу | Выведите её рядом с запуском сервера |
| Переменная не пустая | Пустая строка игнорируется — пароль останется из `config.yml` |
| Приоритет | Переменная **важнее** `database.mysql.password` |
| После смены | Нужен перезапуск сервера |

### Права на папку плагина

Для SQLite плагин должен создать файл `data.db`:

```bash
# Проверка прав
ls -la plugins/DC-CustomItems/
chown -R <пользователь сервера> plugins/DC-CustomItems/
```

## Ошибка database is locked

### Симптом

В логе:

```text
SQL error: database is locked
```

### Причина

**SQLite** хранит всю базу в одном файле и разрешает только одну запись одновременно. Когда два потока пишут в файл в один момент, SQLite возвращает эту ошибку.

Сам плагин от этого защищён: доступ к общему соединению **сериализуется** (операции выполняются по очереди, а не параллельно). Поэтому чаще всего проблема в одном из двух:

| Причина | Что делать |
|---------|------------|
| Другой плагин пишет в тот же `data.db` | Проверьте, не использует ли кто-то ещё этот файл. Свои данные держите в своей таблице, но файл базы общий |
| Ваш код делает тяжёлые записи в главном потоке | Перенесите запросы в асинхронные методы: `executeAsync`, `queryIntAsync`, `queryAllAsync` |

Как проверить, не мешает ли другой плагин:

```bash
# Кто ещё открывает data.db
lsof plugins/DC-CustomItems/data.db

# Windows
handle.exe plugins/DC-CustomItems\data.db
```

### Решение для своего кода

```java
// Плохо: тяжёлая запись в главном потоке
plugin.getDatabaseManager().execute("UPDATE ... ");

// Хорошо: асинхронно
plugin.getDatabaseManager().executeAsync("UPDATE ... ");
```

А если данных стало много — переходите на MySQL: там записи не блокируют друг друга. См. [База данных](12-database.md).

## Сервер лагает

### Симптом

TPS просел, на сервере «пики» (lag spike) — игроки жалуются на задержки.

### Что делает плагин

| Механизм | Нагрузка | Как уменьшить |
|----------|----------|---------------|
| Проверка экипировки | Раз в **150 мс** на игрока читаются ID предметов в 6 слотах | Уменьшите количество предметов с эффектами и атрибутами |
| Обновление версии | Один HTTP-запрос к GitHub при старте, **в фоновом потоке** | Ничего: он и так не блокирует сервер. Если сервер без интернета — будет лишь предупреждение в лог |
| Обработка движения | `onMove` вызывается при реальном перемещении | Не пишите тяжёлую логику в `onMove` |

### Что обычно вызывает лаги

| Причина | Почему | Решение |
|---------|--------|---------|
| Тяжёлый код в `onMove` | Событие движения срабатывает ~20 раз в секунду на игрока | Оставьте в `onMove` только расчёты; тяжёлое (запись в базу, телепорт) делайте по кулдауну |
| SQL-запрос в обработчике события | JDBC блокирует главный поток | Используйте `executeAsync` / `queryIntAsync` |
| Слишком много `.java`-файлов | Компиляция при каждом `/ci reload` | Не держите лишние файлы в `items/` |
| Много эффектов и атрибутов | Пересчёт при каждом изменении инвентаря | Уберите эффекты с предметов, которые редко носят |
| Огромные `lore` | Рендеринг длинного описания | Сократите `lore` |
| Частые частицы | Следы частиц спавнятся каждый тик | Увеличьте `trail-particle-interval` |

### Как измерить

| Инструмент | Что покажет |
|------------|-------------|
| `/timings` (Paper) | Какие плагины и задачи едят время |
| `spark` | Профилирование сервера |
| `debug-mode: true` + `/ci reload` | Статистика кэша перечислений плагина |

Проверьте, что дело не в плагине: временно выгрузите `DC-CustomItems.jar` и посмотрите, изменились ли TPS.

## Предмет исчез

### Симптом

Предмет был в инвентаре и пропал. Иногда игрок получает сообщение, иногда — нет.

### Три причины

| Причина | Как понять | Что делать |
|---------|-----------|------------|
| **Истёк срок жизни** (`duration`) | Игрок получил сообщение «Предмет истёк» (или `max-duration-message`) | Уберите `duration` или увеличьте его |
| **Кончились заряды** (`max-uses`) | Игрок получил сообщение «Предмет израсходован» (или `uses-depleted-message`) | Уберите `max-uses` или выдайте новый предмет |
| **Предмет запрещён в этом мире** | Игрок получил сообщение «Предмет запрещён в этом мире» | Проверьте `allowed-worlds` / `disabled-worlds` |

Подробности:

| Ключ | Как работает |
|------|--------------|
| `duration` | Время жизни в секундах, считается от момента выдачи. Проверяется раз в секунду |
| `max-uses` | Сколько раз можно использовать. Счётчик хранится в самом предмете и виден в `lore` как `%uses%` |
| `allowed-worlds` | Список миров, где предмет разрешён. Пустой список — разрешён везде |
| `disabled-worlds` | Список миров, где предмет запрещён |

Обратите внимание: предметы `CONSUMABLE` исчезают **по расходу** — это нормальное поведение, а не ошибка.

Если предмет исчез и сообщения не было — скорее всего, это `duration` или `max-uses` с отключённым сообщением. Проверьте ключи `max-duration-message` и `uses-depleted-message`.

## Как читать лог плагина

### Включить файловый лог

По умолчанию (`file-logging: false`) плагин пишет в консоль сервера. Если консоль забита, включите отдельный файл:

```yaml
# config.yml
file-logging: true
```

После этого:

```text
plugins/DC-CustomItems/logs/
├── latest.log          ← текущий лог
└── archive/
    ├── 2026-10-20_22-15-30.log
    └── 2026-10-21_09-00-12.log
```

При каждом старте сервера `latest.log` переносится в `archive/` с меткой времени, а новый лог пишется заново.

> Когда `file-logging` включён, сообщения плагина **уходят в файл, а не в консоль**. Не пугайтесь, что консоль стала тише.

### Формат строки

```text
[2026-10-21 14:25:30.123] [INFO] [JavaCompiler] Compiled: 2, Skipped: 1 (120ms)
```

| Часть | Что это |
|-------|---------|
| `[2026-10-21 14:25:30.123]` | Дата и время с миллисекундами |
| `[INFO]` | Уровень: `INFO`, `WARNING`, `SEVERE` |
| Дальше | Текст сообщения |

### Уровни

| Уровень | Что значит |
|---------|-----------|
| `INFO` | Обычное сообщение: что загрузилось, что скомпилировалось |
| `WARNING` | Стоит проверить: неизвестный атрибут, неизвестный эффект, нет секции бонуса, опасный вызов в `.java` |
| `SEVERE` | Ошибка: предмет не загрузился, файл не скомпилировался, база не подключилась |

### Что искать при разных проблемах

| Проблема | Что искать в логе |
|----------|------------------|
| Предмет не загрузился | `Error while loading item`, `Section 'item' not found`, `Unknown material` |
| Java-файл не собрался | `[JavaCompiler] ❌` |
| Java-файл собрался | `[JavaCompiler] Compiled: N, Skipped: M` |
| Команда не зарегистрирована | `[API] Registered command: /имя` |
| База | `Database connected: SQLite` / `Database connected: MySQL` |
| Ошибки SQL | `SQL error:`, `Query error:` |
| Ошибки прав | `No permission!` (в чате игрока), а не в логе |

### Быстрый просмотр в Linux

```bash
# Последние 50 строк
tail -n 50 plugins/DC-CustomItems/logs/latest.log

# Искать ошибки
grep -i "severe\|error\|❌" plugins/DC-CustomItems/logs/latest.log

# Следить за логом в реальном времени
tail -f plugins/DC-CustomItems/logs/latest.log
```

## Как просить о помощи

Чем больше информации вы приложите, тем быстрее вам ответят. Соберите **минимум** такой набор:

| Что | Зачем | Как получить |
|-----|-------|--------------|
| Версия плагина | Разные версии ведут себя по-разному | `plugins/DC-CustomItems/logs/latest.log` или `plugin.yml` |
| Версия сервера и Java | Часто причина в несовместимости | В консоли при старте сервера |
| Вывод консоли | Главный источник ошибок | Скопируйте **всё** от строки с `[DC-CustomItems]` до конца ошибки |
| YAML-предмет | Показывает, что не так с описанием | Пришлите **весь файл**, а не кусок |
| Файл `.java` | Если не компилируется | Пришлите файл и текст ошибки из лога |
| Значение `java-compilation` | Влияет на то, что вообще может работать | `config.yml` |
| Что ожидалось и что получилось | Описание проблемы | Пишите словами |

Полезный шаблон:

```text
Версия плагина: 1.333.0
Сервер: Paper 1.21.8 (Java 21)
java-compilation: true

Что делаю: /ci reload
Что ожидаю: предмет появляется в /give
Что получаю: в консоли ошибка:

[JavaCompiler] ❌ my-item.java:12 - cannot find symbol
    symbol:   method getPerk()
    location: class myItem

Файл: plugins/DC-CustomItems/items/my-item.java
```

И ещё одно: перед вопросом попробуйте включить `debug-mode: true`, сделать `/ci reload` и приложить вывод — так в логе будет видно больше деталей.
