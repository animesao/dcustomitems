## Что такое триггер

**Триггер** — это условие, при котором предмет «оживает» и выполняет заданные действия.

Разница между действием и триггером:

| | Действие | Триггер |
|---|----------|---------|
| Что это | Команда: «вылечить», «ударить», «показать текст» | Событие: «при убийстве», «при прыжке» |
| Когда срабатывает | Сразу после нажатия | Автоматически, когда произошло событие |
| Где живёт | `left-click-actions`, `right-click-actions` | Раздел `triggers:` |

Проще говоря: **действие — это «что сделать», триггер — это «когда сделать»**.

Один триггер может содержать сколько угодно действий.

## Формат в YAML

Раздел `triggers:` находится на верхнем уровне предмета (рядом с `item:`, `effects:`, `triggers:`).

```yaml
my-item:
  item:
    type: NETHERITE_SWORD
    title: '&cМеч'

  triggers:
    on_kill:
      - 'heal:20'
      - 'sound:ENTITY_PLAYER_LEVELUP:1:2'
    on_click_right:
      - 'effect:STRENGTH:10:2'
```

Правила формата:

| Правило | Описание |
|---------|----------|
| Ключ | Имя триггера: `on_kill`, `on_click_right` и т.д. **Пишется строго как в документации** — с маленькой буквы и с подчёркиванием. Регистр здесь важен (в отличие от имён действий) |
| Значение | Список строк-действий в одинарных кавычках `'...'` |
| Разделитель параметров | Двоеточие `:` |
| Порядок | Действия выполняются сверху вниз, в порядке списка |

> Старый ключ `trigger-actions:` удалён начиная с версии 1.328 и игнорируется. Если вы скопировали старый пример — перепишите его в формат `triggers:`.

Внутри одного предмета можно использовать сколько угодно разных триггеров:

```yaml
  triggers:
    on_equip:
      - 'particles:PORTAL:30'
    on_unequip:
      - 'particles:SMOKE:20'
    on_click_left:
      - 'damage_nearby:20:4'
    on_click_right:
      - 'effect:STRENGTH:10:2'
    on_kill:
      - 'heal:40'
    on_death:
      - 'message:&cВы погибли...'
    on_damage_taken:
      - 'effect:RESISTANCE:5:2'
    on_damage_dealt:
      - 'heal:6'
    on_jump:
      - 'effect:JUMP_BOOST:3:1'
    on_sprint:
      - 'effect:SPEED:5:1'
    on_pickup:
      - 'message:&aВы подобрали клинок'
    on_drop:
      - 'message:&7Вы выбросили клинок'
```

## Список всех триггеров

| Триггер | Когда срабатывает | Примечания |
|---------|-------------------|------------|
| `on_click_left` | Игрок кликнул **левой** кнопкой мыши по предмету | Предмет должен быть в руке, которой кликнули. Работает и в воздухе, и по блоку |
| `on_click_right` | Игрок кликнул **правой** кнопкой мыши по предмету | То же условие. У предметов типа `CONSUMABLE` (расходники) клик не доходит до триггера: расходник сразу исчезает |
| `on_equip` | Предмет **надели** в слот активации | Слот задаётся ключом `activation-slot`: `HAND`, `OFFHAND`, `HEAD`, `CHEST`, `LEGS`, `FEET` |
| `on_unequip` | Предмет **сняли** с слота активации | |
| `on_kill` | Игрок **убил** моба или другого игрока | Проверяются предметы убийцы: рука, вторая рука и любой слот брони |
| `on_death` | Игрок с этим предметом **умер** | Проверяются предметы погибшего |
| `on_damage_taken` | Игрок **получил** урон | Проверяются предметы пострадавшего |
| `on_damage_dealt` | Игрок **нанёс** урон | Учитываются и выстрелы из лука/арбалета: срабатывает у стрелка |
| `on_jump` | Игрок **прыгнул** | Не чаще одного раза в 500 мс — защита от «дребезга» |
| `on_sprint` | Игрок **начал бежать** | Только начало бега; остановка бега не вызывает срабатывание |
| `on_pickup` | Игрок **подобрал** предмет | Срабатывает на самом подборе, до того как предмет попадёт в инвентарь |
| `on_drop` | Игрок **выбросил** предмет | Срабатывает в момент броска |

### Как триггеры находят предмет

Для триггеров `on_kill`, `on_death`, `on_damage_taken`, `on_damage_dealt`, `on_jump`, `on_sprint` плагин проверяет **шесть слотов** игрока:

1. Основная рука
2. Вторая рука
3. Шлем
4. Нагрудник
5. Поножи
6. Ботинки

Слот активации при этом **не важен** — триггер сработает, даже если предмет лежит не там, где прописано `activation-slot`. Слот активации влияет только на `on_equip` / `on_unequip` и на постоянные `effects` / `attributes`.

## Несколько действий в одном триггере

В одном триггере может быть сколько угодно действий. Они выполняются **строго по порядку**, сверху вниз:

```yaml
    on_click_right:
      - 'title:&cОгонь!|&7Пламя|10|40|10'   # 1 — заголовок
      - 'particles_custom:FLAME:200:0:1:0:3:1:3' # 2 — частицы
      - 'damage_custom:30:6:4:6'                  # 3 — урон
      - 'sound:ENTITY_BLAZE_SHOOT:1:1'             # 4 — звук
```

Что важно знать:

- Если одно действие завершится ошибкой, **остальные всё равно выполнятся** — плагин ловит исключение, пишет его в консоль и идёт дальше.
- Действия с задержками (`command_sequence`, `teleport_sequence`, `effect_sequence`) возвращают управление сразу, а сама последовательность разворачивается по таймеру. Следующее действие в списке начнётся, не дожидаясь конца последовательности.
- Псевдо-действие `cooldown:MS` обрабатывается отдельно: его можно поставить в любое место списка, и оно не выполнится как обычное действие, а только задаст задержку (см. следующий раздел).

## Задержки

Есть два независимых механизма задержек.

### 1. `click-cooldown` — задержка клика

Ключ `click-cooldown` на верхнем уровне предмета задаёт задержку в **миллисекундах** между кликами по предмету.

```yaml
fire-sword:
  click-cooldown: 2000   # 2 секунды
```

Как это работает:

| Что происходит | Поведение |
|----------------|-----------|
| Игрок кликнул предмет | Действия и триггеры клика выполняются, запускается отсчёт |
| Игрок кликнул ещё раз раньше, чем прошло 2000 мс | Клик **полностью игнорируется**: ни `left-click-actions`, ни `right-click-actions`, ни триггеры `on_click_left` / `on_click_right` не выполняются. Игрок увидит сообщение из `cooldown-message` (если оно задано) |
| Прошло 2000 мс | Следующий клик снова сработает |

Дополнительно: пока активна задержка клика, **не срабатывают и другие триггеры этого предмета** — например, `on_kill` и `on_sprint`. Причина техническая: задержка записывается как «предмет + триггер», и для триггеров, идущих не от клика, она тоже блокирует срабатывание.

Если `cooldown-message` не задан, игрок просто ничего не видит. Плейсхолдер `{seconds}` в сообщении показывает, сколько секунд осталось.

### 2. `cooldown:MS` — задержка конкретного триггера

Псевдо-действие `cooldown:MS` ставит задержку **только для того триггера**, в котором оно указано.

```yaml
vampire-blade:
  triggers:
    on_kill:
      - 'cooldown:5000'    # on_kill — не чаще раза в 5 секунд
      - 'heal:40'
      - 'effect:REGENERATION:15:3'
    on_click_right:
      - 'effect:STRENGTH:8:2'
```

| Правило | Описание |
|---------|----------|
| Где работает | Только внутри `triggers:` |
| Формат | `имя_триггера:cooldown:МС` |
| Единица | Миллисекунды (`3000` = 3 секунды) |
| По умолчанию | `3000`, если число не разобралось |
| Область | Пара «игрок + предмет + триггер» |
| Приоритет | Если в триггере есть `cooldown:MS`, оно **заменяет** `click-cooldown` для этого триггера |
| Несколько `cooldown` | Побеждает наибольшее значение |
| Положение в списке | Не важно — можно поставить первым или последним |

Пока задержка активна, **весь триггер пропускается целиком** — ни одно его действие не выполняется.

Разница между двумя механизмами:

| | `click-cooldown` | `cooldown:MS` |
|---|------------------|---------------|
| Что блокирует | Клик по предмету целиком | Только тот триггер, где указан |
| Затрагивает другие триггеры | Да (`on_kill`, `on_sprint` тоже перестают срабатывать) | Нет |
| Где задаётся | Ключ рядом с `item:` | Внутри списка действий триггера |
| Несколько значений | Одно на предмет | Своё на каждый триггер |

## Несколько предметов у игрока

Если у игрока одновременно есть несколько предметов с триггерами, **срабатывают все подходящие**.

Пример: у игрока в руке «вампирский клинок» (`on_kill: heal:40`), а на голове «амулет регенерации» (`on_kill: effect:REGENERATION:15:3`). Когда игрок кого-то убивает:

1. Срабатывает `on_kill` у клинка — лечение.
2. Срабатывает `on_kill` у амулета — регенерация.

Каждый предмет работает сам по себе, задержки считаются отдельно для каждой пары «предмет + триггер».

Важные детали:

- В пределах одного предмета задержка общая: если предмет в руке и тот же предмет в броне (невозможно, но если предмет — расходник и разные стопки) — это разные предметы, у них разные ключи задержки.
- Один и тот же предмет не срабатывает дважды за одно событие в одном слоте.

## Готовые примеры

### Вампирский клинок

Клинок лечит владельца при убийстве и немного — при нанесении урона.

```yaml
vampire-blade:
  type: TOOL
  activation-slot: HAND
  click-cooldown: 2000

  item:
    type: NETHERITE_SWORD
    title: '&4[🦇] &fКлинок вампира'
    glowing: true
    unbreakable: true

  triggers:
    on_equip:
      - 'particles:DRAGON_BREATH:20'
      - 'sound:ENTITY_WITHER_AMBIENT:1:1.2'
      - 'message:&4👁 &7Вы почувствовали жажду крови!'

    on_unequip:
      - 'particles:SMOKE:15'
      - 'sound:ENTITY_ENDER_DRAGON_GROWL:0.5:1.5'

    on_click_right:
      - 'effect:STRENGTH:8:2'
      - 'effect:REGENERATION:10:3'
      - 'title:&4🦇 &7КРОВОПИЙСТВО!|&cЗдоровье воруется!|10|40|10'

    on_click_left:
      - 'damage_nearby:20:4'
      - 'knockback:4'

    on_kill:
      - 'heal:40'
      - 'effect:REGENERATION:15:3'
      - 'sound:ENTITY_PLAYER_LEVELUP:1:2'

    on_damage_dealt:
      - 'heal:6'
      - 'particles:DRAGON_BREATH:12'
```

### Предмет с эффектом при подборе

```yaml
lucky-charm:
  type: RUNE
  activation-slot: HAND

  item:
    type: GOLD_NUGGET
    title: '&eСчастливый талисман'
    glowing: true

  triggers:
    on_pickup:
      - 'message:&eВы нашли талисман удачи!'
      - 'effect:REGENERATION:10:2'
      - 'particles:END_ROD:30'
      - 'sound:ENTITY_PLAYER_LEVELUP:1:1.5'

    on_drop:
      - 'message:&7Вы уронили талисман.'
      - 'particles:SMOKE:20'
```

### «Аура» при беге

Задержка `cooldown:500` не даёт эффекту накладываться каждый кадр.

```yaml
aura-ring:
  type: ARMOR
  activation-slot: HAND

  item:
    type: ECHO_SHARD
    title: '&dКольцо ауры'

  triggers:
    on_sprint:
      - 'cooldown:500'
      - 'effect_nearby_mobs:WEAKNESS:6:1:5'
      - 'particles:SOUL:40'
      - 'sound:ENTITY_WITHER_SHOOT:0.5:2'
```

### Зелье здоровья на каждое убийство

```yaml
blood-elixir:
  type: CONSUMABLE
  activation-slot: HAND
  max-uses: 5

  item:
    type: GLOWSTONE_DUST
    title: '&cЭликсир крови'

  triggers:
    on_kill:
      - 'cooldown:2000'
      - 'heal:30'
      - 'effect:REGENERATION:20:4'
      - 'particles_custom:HEART:100:0:2:0:2:2:2'
      - 'fireworks:1'
```

### Сапог с прыжком

```yaml
jump-boots:
  type: ARMOR
  activation-slot: FEET

  item:
    type: LEATHER_BOOTS
    title: '&bПрыгающие ботинки'

  triggers:
    on_jump:
      - 'effect:JUMP_BOOST:5:2'
      - 'particles:CLOUD:10'
      - 'sound:ENTITY_BREEZE_JUMP:1:1.5'
```

### Полный набор триггеров на одном предмете

```yaml
guardian-shield:
  type: ARMOR

  item:
    type: SHIELD
    title: '&6Щит защитника'

  triggers:
    on_equip:
      - 'particles:HAPPY_VILLAGER:20'

      - 'particles:SWEEP_ATTACK:15'

      - 'cooldown:3000'
      - 'effect:RESISTANCE:8:2'
      - 'particles:ENCHANTMENT_TABLE:30:0:1:0:1:1:1'
      - 'sound:ITEM_SHIELD_BLOCK:1:1.2'

    on_damage_dealt:
      - 'knockback:2'
```

## Триггер не срабатывает

Проверяйте по порядку — чаще всего дело в первых двух пунктах.

### 1. Предмет в нужном слоте

| Триггер | Где должен лежать предмет |
|---------|---------------------------|
| `on_equip` / `on_unequip` | В слоте из `activation-slot` |
| `on_click_left` / `on_click_right` | В руке, которой кликнули |
| `on_kill`, `on_death`, `on_damage_taken`, `on_damage_dealt`, `on_jump`, `on_sprint` | В руке, второй руке или в любом слоте брони |
| `on_pickup` / `on_drop` | Слот не важен |

### 2. Имя триггера написано верно

Имя триггера чувствительно к регистру и должно совпадать со списком выше:

```yaml
  triggers:
    on_kill:      # ✅ верно
      - 'heal:20'
```

```yaml
  triggers:
    onKill:      # ❌ не сработает
      - 'heal:20'
    ON_KILL:     # ❌ не сработает
      - 'heal:20'
    on-kill:     # ❌ не сработает (в именах триггеров дефис не допускается)
      - 'heal:20'
```

### 3. Предмет действительно ваш

Триггеры работают только с предметами, созданными плагином (у них есть специальная метка в данных предмета). Если предмет выдан сторонним плагином или переименован вручную через аниvil — он не сработает.

### 4. Активна ли задержка

- Проверьте `click-cooldown` у предмета: пока он активен, клик игнорируется полностью.
- Проверьте `cooldown:MS` в самом триггере: пока он активен, триггер пропускается целиком.

### 5. Смотрите лог

Сообщения об ошибках в действиях пишутся в консоль сервера:

```text
[DC-CustomItems] Error executing action: effect:SPED:10 - ...
```

Проверить состояние предмета можно командой:

```bash
/ci debug vampire-blade
```

Она покажет тип, слот активации, задержку, количество использований и список разделов с рецептами. Если предмет вообще не найден — значит, он не загрузился: проверьте имя файла в папке `items/` (файлы с префиксом `EXAMPLE-` не загружаются) и выполните `/ci reload`.

### 6. Событие было отменено

Если на сервере есть другие плагины, они могут отменять входящий урон или смерть. Тогда триггеры `on_damage_*`, `on_kill` и `on_death` не сработают. Проверьте лог на предметы других плагинов.
