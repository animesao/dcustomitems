# DC-CustomItems — Вики

Полное руководство по плагину **DC-CustomItems**: от установки до собственных
модулей. Написано для новичка — можно читать с начала и не пропускать.

> Плагин делает одну простую вещь: **даёт вам предметы, которые вы описали
> сами** — в YAML или на Java. Всё остальное (предметы, команды, плейсхолдеры,
> модули, рецепты, сообщения) лежит обычными файлами в папке `items/` и
> включается копированием файла. Ничего не надо компилировать «вручную».

---

## С чего начать (5 минут)

1. **[Установка](01-getting-started.md)** — скачать, положить в `plugins/`, проверить.
2. **[Как это работает](02-how-it-works.md)** — что такое папка `items/`
   и почему плагин создаёт ровно один файл.
3. Откройте `plugins/DC-CustomItems/items/messages.java` — это **все тексты
   плагина**. Правьте и пишите `/ci reload`.

Первый предмет — в разделе [Примеры](16-examples.md), самый простой —
в [Предметы (YAML)](03-yaml-items.md).

## Главное за 60 секунд

**Всё, что вы настраиваете, лежит в одной папке:**

```
plugins/DC-CustomItems/
├── config.yml          # настройки плагина (создаётся сам)
└── items/              # ВАШ КОНТЕНТ — единственное, что нужно править
    ├── messages.java   # все тексты плагина (создаётся сам)
    ├── my-item.yml     # предмет
    ├── my-command.java # команда
    └── my-module/      # модуль (папка с config.yml и .java)
```

**Три команды, которые нужны почти всегда:**

| Команда | Что делает |
|---------|-----------|
| `/ci reload` | Перечитать все файлы из `items/` (после любой правки) |
| `/ci validate` | Проверить рецепты и найти опечатки в YAML |
| `/ci debug <id>` | Показать, как плагин «видит» конкретный предмет |

**Три способа описать предмет:**

| Способ | Когда использовать |
|--------|-------------------|
| YAML | 90% случаев: эффекты, атрибуты, сеты, рецепты, лор |
| Java | Нужна логика: проверки, особое поведение, свой таймер |
| Модуль | Переиспользуемый кусок: магазин, меню, своя экономика |

## Частые вопросы

**Нужно ли что-то компилировать?**
Нет. Java-файлы из `items/` плагин компилирует сам при `/ci reload`
(ему нужен JDK на сервере, а не JRE — см. [Установку](01-getting-started.md)).

**Можно ли удалить плагин, если он не нужен?**
Да, удалите папку `plugins/DC-CustomItems` — контент пропадёт вместе с ней.
Перед этим сделайте `/ci backup`.

**Как сделать резервную копию?**
`/ci backup` — копия `items/`, `config.yml` и `data.db` в
`plugins/DC-CustomItems/backups/`. По умолчанию бэкап создаётся и перед
каждым `/ci reload` (`backup.on-reload`).

**Плагин на английском — а можно по-русски?**
Да. Все тексты — в `items/messages.java`, переведите нужные строки и
сделайте `/ci reload`. Подробно — в [Сообщениях](11-messages.md).

**Где взять примеры?**
В репозитории, в папке [`samples/`](https://github.com/animesao/dcustomitems/tree/main/samples).
Скопируйте нужный файл в `items/`, уберите префикс `EXAMPLE-` и сделайте
`/ci reload`.
