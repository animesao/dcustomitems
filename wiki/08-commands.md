## Две разные вещи: встроенная команда и свои команды

**Команда** — это то, что игрок пишет в чат, чтобы что-то сделать: `/ci`, `/shop`, `/heal`.

В DC-CustomItems команды бывают двух видов:

| Вид | Где живёт | Пример |
|-----|-----------|--------|
| Встроенная | Внутри плагина, всегда доступна | `/ci reload` |
| Своя | Ваш `.java`-файл в папке `items/` | `/heal`, `/berserk`, `/shop` |

Встроенная команда у плагина **одна** — `/ci` (полное имя `customitems`). Всё остальное — магазин, крафт, меню — приезжает **модулями** (см. [Модули](10-modules.md)) или пишется вами руками.

> **Важно.** Команды предметов (`/give`, `/api-item …`), которые упоминались в старых версиях плагина, в текущей версии **не существуют**. Список команд всегда можно посмотреть в консоли сервера при старте.

## Встроенная команда ci

Команда объявлена в `plugin.yml`:

```yaml
commands:
  customitems:
    description: Reload plugin
    usage: /customitems reload
    aliases: [ci]
    permission: dcustomitems.reload
```

Значит:

- Основное имя — `/customitems`, короткое — `/ci`.
- Право — `dcustomitems.reload` (по умолчанию выдаётся операторам).
- Если у игрока нет права, он вообще не видит команду в подсказках и не может её вызвать.

| Подкоманда | Что делает | Право |
|------------|-----------|-------|
| `/ci reload` | Перечитывает всё: `config.yml`, YAML-предметы, бонусы комплектов, `.java`-файлы (предметы, команды, плейсхолдеры) и модули | `dcustomitems.reload` |
| `/ci validate` | Проверяет рецепты YAML-предметов (`shaped` и `shapeless`) и печатает список найденных проблем | `dcustomitems.reload` |
| `/ci debug <id>` | Печатает техническую информацию о YAML-предмете: тип, слот активации, материал, заряды, кулдаун, рецепты, число ключей NBT | `dcustomitems.reload` |
| `/ci backup` | Создаёт резервную копию папки `items/` (а также `config.yml` и `data.db`) в `plugins/DC-CustomItems/backups/` | `dcustomitems.reload` |

**`/ci` без аргументов** — это то же самое, что `/ci reload`.

### Подкоманда reload

Порядок работы (важно понимать, что именно перечитывается):

1. **Резервная копия** — если в `config.yml` включено `backup.on-reload: true` (по умолчанию), перед перезагрузкой создаётся копия. Старые копии удаляются, их количество задаёт `backup.keep` (по умолчанию 5).
2. `config.yml` — перечитывается.
3. **YAML-предметы** — заново читаются все `.yml` из `items/`.
4. **Бонусы комплектов** — перечитываются из `config.yml` (раздел `set-bonuses`).
5. **Java API** — заново компилируются все `.java` из `items/`: предметы, команды, плейсхолдеры, модули. Старые команды снимаются с сервера, новые регистрируются.
6. **`items/messages.java`** — применяется заново (см. [Сообщения](11-messages.md)).
7. **Модули** — выгружаются и загружаются заново (см. [Модули](10-modules.md)).

Ответ в чат выглядит примерно так:

```text
[DCI] Plugin reloaded!
[DCI] YAML items: 12
[DCI] Java items: 3
[DCI] Java commands: 2
[DCI] Java placeholders: 1
[DCI] Modules: 4
```

Строка `Java commands: 2` — это и есть количество **ваших** команд из `items/*.java`.

Если в `config.yml` включён `debug-mode: true`, после перезагрузки дополнительно печатается статистика внутреннего кэша перечислений (`EnumCache`) — для тонкой диагностики.

### Подкоманда validate

Проверяет рецепты всех YAML-предметов:

- в `shaped` — правильность сетки (`pattern`) и то, что все буквы описаны в `keys`, а материалы и id ингредиентов существуют;
- в `shapeless` — что ингредиенты существуют.

Каждая проблема печатается красным, в конце — итог:

```text
Validation OK: no problems found.
```

или

```text
Validation: problems found: 2
```

### Подкоманда debug

Выгружает «внутренности» одного YAML-предмета. Нужен, когда предмет ведёт себя не так, как ожидается.

```bash
/ci debug vampire-blade
```

Пример вывода:

```text
vampire-blade type=RUNE slot=HAND
material=DIAMOND_SWORD uses=25 cd=0
recipes=[shaped]
pdc-keys=1
```

Ограничения:

- Ищет **только YAML-предметы**. Java-предмет в `items/*.java` этой командой не покажется — используйте `/ci reload` и логи.
- Идентификатор приводится к нижнему регистру, регистр писать не обязательно.

### Подкоманда backup

Создаёт папку `plugins/DC-CustomItems/backups/items-YYYYMMDD-HHMMSS/` и копирует туда:

- всю папку `items/` (включая вложенные папки модулей);
- `config.yml`;
- `data.db` (база данных SQLite), если она есть.

Старые копии удаляются, их число задаёт `backup.keep` в `config.yml`. MySQL-база в копию не попадает — её бекапите своими средствами.

### Автодополнение у ci

Наберите `/ci ` и нажмите Tab — плагин подскажет `reload`, `validate`, `debug`, `backup`. Для `/ci debug ` подсказками будут id ваших YAML-предметов.

## Своя команда: файл в items

Своя команда — это обычный `.java`-файл в папке `items/`:

```text
plugins/DC-CustomItems/items/
├── messages.java
├── heal-command.java      ← ваша команда
└── my-item.yml
```

Плагин при старте (и на каждой `/ci reload`) просматривает `items/`, находит `.java`-файлы и компилирует их на лету. Если класс наследует `CustomCommand` — он становится командой сервера.

Требования к файлу:

| Требование | Почему |
|------------|--------|
| Класс объявлен как `public class ИмяКласса` | Компилятор читает только `public`-классы и переименовывает их |
| Есть публичный конструктор без аргументов | Плагин создаёт команду через `new` без параметров |
| Класс наследует `CustomCommand` | По этой строке плагин понимает, что это команда, а не предмет или плейсхолдер |
| Файл лежит в `items/` (или в подпапке) | Другие папки плагин не сканирует |

### Полный рабочий пример

Файл `plugins/DC-CustomItems/items/heal-command.java`:

```java
import me.dcplugin.dcustomitems.api.commands.CustomCommand;
import org.bukkit.attribute.Attribute;
import org.bukkit.command.CommandSender;
import org.bukkit.entity.Player;

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

/**
 * /heal — полностью лечит игрока.
 *
 * Что делать: положите файл в plugins/DC-CustomItems/items/
 * и выполните /ci reload.
 */
public class HealCommand extends CustomCommand {

    public HealCommand() {
        super(
                "heal",                             // имя команды
                "Вылечить себя или другого игрока",  // описание (видно в /help)
                "/heal [игрок]",                    // подсказка по использованию
                "dci.command.heal",                 // право
                "healme"                            // альтернативное имя
        );
    }

    @Override
    public boolean execute(CommandSender sender, String[] args) {
        // getTarget: если аргумент есть — берём этого игрока,
        // если нет и команду вызвал игрок — берём самого себя.
        // Если игрока нет — метод сам отправляет сообщение и вернёт null.
        Player target = getTarget(sender, args, 0);
        if (target == null) return true;

        double maxHealth = target.getAttribute(Attribute.MAX_HEALTH).getValue();
        target.setHealth(maxHealth);
        target.setFoodLevel(20);

        msg(sender, "&aГотово: &e" + target.getName());
        title(target, "&a❤ Лечение!", "&7Здоровье и сытость восстановлены");
        return true;
    }

    @Override
    public List<String> tabComplete(CommandSender sender, String[] args, int cursor) {
        if (cursor == 0) {
            // Подсказываем ники игроков онлайн
            List<String> names = new ArrayList<>();
            for (Player p : sender.getServer().getOnlinePlayers()) {
                names.add(p.getName());
            }
            return names;
        }
        return Collections.emptyList();
    }
}
```

После `/ci reload` в консоли появится:

```text
[API] Command: /heal
```

и появится сама команда. Право `dci.command.heal` нужно выдать игрокам (см. [Права](15-permissions.md)).

### Имя класса и имя файла

Правило простое: **имя файла и имя класса не обязаны совпадать**.

Компилятор плагина работает не как обычный `javac`:

1. Берёт путь файла относительно `items/` и превращает его в корректное Java-имя: любые символы, кроме букв, цифр и `_`, заменяются на `_`, в конце добавляется `Item`.
   - `items/heal-command.java` → `heal_commandItem`
   - `items/shop/shop.java` → `shop_shopItem`
2. Затем **переименовывает сам класс** в исходнике на это сгенерированное имя.

Из этого следуют два практических вывода:

| Что | Правило |
|-----|---------|
| Имя класса | Должно начинаться с `public`. Имя может быть любым — плагин переименует класс сам. |
| Имя файла | Не обязано совпадать с классом. Но для порядка называйте файл так же, как команда: `heal-command.java`. |

Дополнительно: если класс **не** `public` (например, `class HealCommand`), плагин его не «увидит», а компиляция упадёт с ошибкой вида «class HealCommand is public, should be declared in a file named …».

### Откуда берётся имя команды

**Имя команды задаётся только в конструкторе** — в первом аргументе `super(...)`:

```java
super("heal", "…", "/heal [игрок]", "dci.command.heal", "healme");
```

| Аргумент | Что это |
|----------|---------|
| `"heal"` | Имя команды. Приводится к нижнему регистру |
| `"Вылечить себя…"` | Описание — видно в подсказках сервера |
| `"/heal [игрок]"` | Подсказка по использованию |
| `"dci.command.heal"` | Право. `null` или `""` — команда доступна всем |
| `"healme"` | Альтернативные имена (можно перечислить несколько) |

Переименовать файл `heal-command.java` в `potion.java` **не** переименует команду — она так и останется `/heal`.

### Конструкторы CustomCommand

В базовом классе есть три конструктора:

```java
// 1. Только имя, без описания и прав
protected CustomCommand()

// 2. Имя, описание, использование, право
protected CustomCommand(String name, String description, String usage, String permission)

// 3. То же + альтернативные имена
protected CustomCommand(String name, String description, String usage, String permission, String... aliases)
```

Третий вариант — самый частый: альтернативные имена передаются обычными строками, а не списком:

```java
super("balance", "Ваш баланс", "/balance [игрок]", "dci.balance", "bal", "money");
```

## Все методы CustomCommand

### Методы, которые нужно или можно переопределить

| Метод | Что делает | Когда переопределять |
|-------|-----------|----------------------|
| `boolean execute(CommandSender sender, String[] args)` | Сама команда. Возвращает `true`, если всё обработано | **Обязательно** — это единственный обязательный метод |
| `List<String> tabComplete(CommandSender sender, String[] args, int cursor)` | Подсказки по Tab. `cursor` — номер позиции, которую дописывает игрок (равен `args.length`) | Если хотите автодополнение |
| `void onRegister()` | Вызывается, когда команда зарегистрирована: при старте сервера и после каждой `/ci reload` | Чтобы подготовить данные, таймеры, подписки |
| `void onUnregister()` | Вызывается перед снятием команды: при `/ci reload` и при выключении плагина | Чтобы убрать эффекты, сохранить состояние, остановить таймеры |
| `boolean hasPermission(CommandSender sender)` | Своя проверка прав. По умолчанию: если право не задано — доступ у всех, иначе `sender.hasPermission(право)` | Если права нужны сложнее, чем «есть/нет» |
| `String getPermissionMessage()` | Текст, который видит игрок без прав | Если нужен свой текст вместо центрального сообщения |
| `void setPermissionMessage(String msg)` | Задать свой текст «нет прав» | В конструкторе или в `onRegister()` |

> **Осторожно с `onUnregister`.** Он вызывается и при перезагрузке, и при выключении сервера. Всё, что он делает, должно быть безопасно выполнять дважды.

### Готовые помощники

Эти методы доступны внутри вашего класса «как свои» — ничего импортировать не нужно:

| Метод | Что делает |
|------|-----------|
| `Player getTarget(CommandSender sender, String[] args, int index)` | Берёт игрока из аргумента `args[index]`. Если аргумента нет и отправитель — игрок, вернёт его самого. Если игрока не существует — **сам отправит сообщение** «Player … not found!» и вернёт `null`. Вернёте `null` — не выполняйте дальнейший код |
| `int getInt(String[] args, int index, int def)` | Читает число из аргумента. Если аргумента нет или он не число — вернёт `def` |
| `double getDouble(String[] args, int index, double def)` | То же самое, но для дробного числа |
| `String joinArgs(String[] args, int start)` | Склеивает аргументы начиная с `start` через пробел. Удобно для текста, например `joinArgs(args, 1)` |
| `void msg(CommandSender sender, String message)` | Отправляет сообщение отправителю. `&`-коды превращаются в цвета автоматически |
| `void msg(Player player, String message)` | То же, но игроку |
| `void title(Player player, String title, String subtitle)` | Показывает крупный заголовок по центру экрана (с подзаголовком). Цвета обрабатываются автоматически |
| `String colorize(String msg)` | Заменяет `&` на `§`. Нужно, если вы отправляете текст мимо `msg()` — например, в `item.setLore()` |
| `String message(String path, String defaultMessage)` | Берёт текст из **центральной системы сообщений** по пути (например `commands.no-permission`). Администратор может переопределить его в `items/messages.java` — см. [Сообщения](11-messages.md) |

Пример использования помощников:

```java
@Override
public boolean execute(CommandSender sender, String[] args) {
    Player target = getTarget(sender, args, 0);
    if (target == null) return true;           // игрока нет — сообщение уже отправлено

    int amount = getInt(args, 1, 1);            // второй аргумент, по умолчанию 1
    double price = getDouble(args, 2, 10.0);
    String comment = joinArgs(args, 3);         // всё после третьего аргумента

    msg(sender, "&a" + amount + " × " + target.getName());
    msg(sender, "&7Комментарий: &f" + comment);
    return true;
}
```

### Геттеры и сеттеры

| Метод | Что делает |
|------|-----------|
| `getName()` / `setName(String)` | Имя команды |
| `getDescription()` / `setDescription(String)` | Описание |
| `getUsage()` / `setUsage(String)` | Подсказка по использованию |
| `getPermission()` / `setPermission(String)` | Право |
| `getAliases()` / `setAliases(String...)` | Альтернативные имена |
| `getPlugin()` / `setPlugin(Main)` | Ссылка на главный класс плагина (её проставляет плагин сам) |

## Права команды

Право задаётся третьим/четвёртым аргументом конструктора:

```java
super("heal", "Лечение", "/heal [игрок]", "dci.command.heal");
```

Как работает проверка:

| Ситуация | Что произойдёт |
|----------|----------------|
| Право не задано (`null` или `""`) | Команда доступна всем, проверка не выполняется |
| Право задано, у игрока оно есть | Команда выполняется |
| Право задано, у игрока его нет | Игрок получает текст «нет прав» и команда **не** выполняется |

Текст «нет прав» берётся из центральной системы сообщений по пути `commands.no-permission`, то есть его можно переопределить в `items/messages.java`. Свою версию можно задать через `setPermissionMessage(...)`.

Дополнительно плагин передаёт право в Bukkit-команду (`Command#setPermission`). Из-за этого команда **скрыта** из `/help` и из подсказок Tab для игроков без права — они её просто не увидят.

Имя права выбирайте сами; оно никак не связано с плагином. В примерах используется схема `dci.command.<имя>`.

## Как команда попадает в CommandMap

**CommandMap** — это список команд, который сервер Minecraft держит в памяти. Обычно туда попадают только команды из `plugin.yml`. Но плагин умеет добавлять туда команды «на лету» — через рефлексию (внутренний API Bukkit, доступ к нему не публичный).

Схема выглядит так:

```text
Игрок пишет /heal
        │
        ▼
Bukkit: находит в CommandMap команду "heal"
        │  (это объект Command, созданный плагином)
        ▼
Command.execute(...)  →  CustomCommandExecutor.onCommand(...)
        │
        ├─ ищет вашу команду по имени/алиасу в реестре ItemRegistry
        ├─ проверяет право (hasPermission)
        ├─ ловит исключения и показывает «Error executing command: …»
        ▼
CustomCommand.execute(sender, args)   ← ваш код
```

Что именно делает `CommandRegistrar`:

1. Для каждой зарегистрированной команды создаёт объект Bukkit `Command` с именем, описанием, использованием и альтернативными именами.
2. Задаёт ему право (`setPermission`).
3. Регистрирует в `CommandMap` с префиксом-запасным вариантом — именем плагина (`dcustomitems`). Это значит, что команда доступна и как `/dcustomitems:heal`.
4. Запоминает созданный объект, чтобы потом убрать его.

Обработчик (одна на все команды — `CustomCommandExecutor`) делает три вещи:

| Шаг | Что происходит |
|-----|----------------|
| Поиск | Команда ищется по имени, затем по альтернативным именам |
| Право | Если права нет — отправляется текст «нет прав», выполнение не происходит |
| Ошибки | Если ваш код бросил исключение — игрок получит «Error executing command: …», а подробности уйдут в консоль с уровнем WARNING |

> **Возвращайте `true` из `execute`.** Значение `false` заставит Bukkit показать игроку строку «использование» команды. Возвращайте `false` только если хотите показать эту подсказку намеренно.

## Что происходит при ci reload

`/ci reload` не перезагружает сервер — он пересобирает плагин «на месте». Для команд это значит:

1. Старые команды **снимаются** с сервера: плагин убирает из `CommandMap` и имя команды, и её альтернативные имена.
2. У всех команд вызывается `onUnregister()` — так вы можете убрать эффекты и сохранить состояние.
3. `.java`-файлы компилируются заново (изменившиеся — по новому хэшу, неизменившиеся — берутся из кэша).
4. Создаются **новые** объекты команд, у новых экземпляров вызывается `onRegister()`.
5. Команды регистрируются в `CommandMap` заново.

Что из этого следует:

| Факт | Почему это важно |
|------|------------------|
| Статические поля класса обнуляются | Класс пересоздаётся заново (новый загрузчик классов). Данные, которые вы держали в `static`-полях, после перезагрузки исчезнут |
| Данные в базе или в файлах остаются | Файлы и база не трогаются — только код |
| Команда, у которой имя совпало с чужой, может не появиться | Если другой плагин уже занял это имя в `CommandMap`, выберите другое |

## Автодополнение своей команды

Переопределите `tabComplete`:

```java
@Override
public List<String> tabComplete(CommandSender sender, String[] args, int cursor) {
    if (cursor == 0) {
        // первое слово после /heal — подсказываем варианты
        return java.util.List.of("all", "self");
    }
    if (cursor == 1) {
        // второе слово — ники игроков
        List<String> names = new ArrayList<>();
        for (Player p : sender.getServer().getOnlinePlayers()) names.add(p.getName());
        return names;
    }
    return Collections.emptyList();
}
```

`cursor` — это количество уже введённых аргументов (`args.length`). Когда игрок только что набрал `/heal `, `cursor` равен 0.

Подсказки не показываются, если у игрока нет права на команду — это делает обработчик до вызова вашего метода.

## Как увидеть список своих команд

Команда **не попадает** в текст `/ci help`: встроенная справка `/ci` — это фиксированный список из четырёх подкоманд плагина (`reload`, `validate`, `debug`, `backup`). Она не собирается из ваших файлов.

Но увидеть свои команды можно:

| Где | Что увидите |
|-----|-------------|
| Консоль при старте сервера | `[API] Custom commands registered: 2` — количество команд |
| Консоль при старте сервера | `[API] Command: /heal` — по строке на каждую команду |
| Ответ на `/ci reload` | `Java commands: 2` — количество команд после перезагрузки |
| Команда `/help` в игре | Описание команд видно там, но **только** у игроков с правом |

Если хотите, чтобы команда была видна всем подряд, заведите для неё право `""` (пустое) — тогда она не будет скрыта из `/help`.

## Команда не появилась: чек-лист

Идите по пунктам сверху вниз — чаще всего хватает первых двух.

| # | Проверьте | Как проверить | Что делать |
|---|-----------|---------------|------------|
| 1 | Файл лежит в `items/` | Путь `plugins/DC-CustomItems/items/файл.java` | Перенесите файл в `items/` |
| 2 | Папка/файл не называется `EXAMPLE-…` | Плагин пропускает `EXAMPLE-*`, `EXAMPLES` и `_template` | Уберите префикс `EXAMPLE-` |
| 3 | Класс `public` и наследует `CustomCommand` | Открыть файл | `public class HealCommand extends CustomCommand` |
| 4 | Есть публичный конструктор без аргументов | Открыть файл | `public HealCommand() { super(...); }` |
| 5 | Java-компиляция включена | `config.yml` → `java-compilation: true` | Включите (иначе `.java` вообще не читаются) |
| 6 | Нет ошибок компиляции | Консоль: строки `[JavaCompiler] ❌ файл:строка - …` | Исправьте ошибку из сообщения |
| 7 | Команда зарегистрирована | Консоль: `[API] Command: /heal` | Нет строки — команда не собрана, вернитесь к пункту 3 |
| 8 | Право выдано | Попробуйте от оператора | Выдайте право: `lp user Steve permission set dci.command.heal true` |
| 9 | Имя совпадает | Что вы вводите в чат vs `super("…")` | Регистр не важен, остальное — важно |

Отдельно про пункт 6: если файл не компилируется, плагин не «падает» — он просто пропускает этот файл и продолжает работу. Ошибка видна только в консоли, поэтому всегда смотрите её после `/ci reload`.

## Частые ошибки

| Ошибка | Как выглядит | Почему |
|--------|--------------|--------|
| Класс не `public` | `class HealCommand is public, should be declared in a file named …` | Плагин переименовывает только `public`-классы |
| Забыли `extends CustomCommand` | Команда не появилась, в консоли нет строки `[API] Command: …` | Плагин определяет тип файла по этой строке |
| Имя команды ≠ имя файла | Игроки жалуются «команды нет» | Имя команды — первый аргумент `super(...)` |
| Опечатка в праве | «You don't have permission!» | Проверьте третье/четвёртое значение `super(...)` и выданное право |
| `return false` из `execute` | Игроку показывается строка «использование» | `false` заставляет Bukkit показать usage |
| Исключение внутри `execute` | Игрок видит «Error executing command: …», в консоли WARNING со стеком | Оберните рискованный код в `try/catch` или исправьте причину |
| Команда пропала после reload | `Unknown command` | Проверьте, что файл не переименовали и что он снова скомпилировался (пункт 7 чек-листа) |
| Команда конфликтует с чужим плагином | `/heal` вызывает чужую команду | Переименуйте свою: `super("dciheal", …)` |
